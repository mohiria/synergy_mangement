# 协作关系模块详细产品需求文档 V1.1

> 版本：V1.1  
> 日期：2026-08-26  
> V1.1 修订（来源：2026-08-25 原型评审，主 PRD V4.5 §0.2）：单行控制栏布局与“图谱／列表”切换文案、KR 节点信息与三态视觉（灰／橙／红描边+图标）、O 深灰底白字、零值隐藏、详情面板字号（16／14／12px），对应新增 CR-21～CR-23。  
> 本文档是《协同管理工具详细 PRD V4.5》中“协作关系”模块的细化说明。若表述冲突，以本文档中已经确认的协作关系规则为准，并同步修正主 PRD。本文档描述产品效果，不强制指定图表库、布局算法、引入方式或调参值。

## 1. 模块定位

协作关系模块是项目事实的只读分析视图，用于回答以下问题：

1. 项目的 O 下有哪些 KR，任务之间又如何通过交付物形成协作网络？
2. 当前任务依赖谁、向谁交付，输入是否已经就绪？
3. 卡点会沿哪些硬前置关系影响其他任务、KR 或 O？
4. 项目是否存在跨 KR／跨 O 依赖、双向协作、反馈循环或硬依赖互锁？
5. 管理者如何从 O／KR 层级视图逐层下钻，又能在需要时查看全局任务关系？

本模块不承担任务、关系、日期、卡点或审核的编辑和处理；相关操作从“全部任务”或“我的工作”进入。

## 2. 目标用户与核心场景

| 用户 | 关注点 | 核心场景 |
|---|---|---|
| 项目总负责人／领导层 | O／KR 层级、风险、关键路径和受影响目标 | 先看 O／KR 层级全景，再按风险或节点逐层下钻 |
| 总推进人 | 跨 KR 协作、卡点、待行动人和输入就绪 | 定位阻塞来源，检查上下游影响并跳转任务处理 |
| KR 负责人 | 本 KR 的输入输出、跨 KR 依赖和互锁 | 检查任务池关系是否完整、关键输入是否就绪 |
| 项目成员 | 自身任务的来源、去向和当前交付状态 | 从任务详情进入图谱，查看一层直接关系并继续展开 |

## 3. 产品目标与非目标

### 3.1 V1 目标

- 默认以纯粹的 O／KR 层级树提供低噪音全局视图，只表达 O 对 KR 的归属关系。
- 支持节点聚焦、逐层展开和全局展开，真实保留多中心、多上下游、跨 O／KR、双向和循环关系。
- 交付物作为有向关系边，当前交付物和候选更新状态附着在边上，不生成交付物节点。
- 支持图谱与关系列表切换，为不习惯图谱的用户提供结构化检查入口。
- 支持风险、卡点、输入就绪、互锁和关键路径的可解释下钻。
- 所有项目成员查看同一份项目事实，权限不改变图谱内容。

### 3.2 V1 非目标

- 不在图谱或关系列表中新增、修改、解除关系。
- 不处理审批、修改日期、上报／解除卡点或发送提醒。
- 不提供泳道图、“查看流程”弹窗或图谱编辑器。
- 不向用户提供布局算法选择。
- 不提供图谱 PNG 导出。
- 不提供任意起止日期筛选。
- 不保存跨会话或跨用户的个人画布布局。
- 不保留交付物历史版本、旧文件或旧文件下载入口。

## 4. 领域结构

### 4.1 层级与关系

项目层级为：

```text
O → KR → 任务
```

任务和实际承担输入责任的项目成员，通过交付物边连接到下游任务：

```text
来源任务／项目成员
→ 交付物边（名称、类型、必要性、提供方、接收方、状态）
→ 下游任务
```

文件、文本或链接等具体交付内容不是独立图谱节点，而是作为当前交付物或审核中的候选交付物关联到交付物边。

### 4.2 节点类型

| 节点 | 出现场景 | 主要信息 |
|---|---|---|
| O | 层级、聚焦、全局展开 | 下属 KR、总体风险 |
| KR | 层级、聚焦、全局展开 | 负责人、任务数量、卡点数量、风险等级 |
| 任务 | KR 展开、任务聚焦、全局展开 | 负责人、生命周期状态、风险等级、结构化卡点、直接上下游、输入就绪情况 |

图谱节点只有 O、KR、任务三类（#159 裁决）。项目成员不形成图谱节点：被指定提供输入的成员在任务详情面板的输入源中表达，数据模型中「成员 → 目标任务」的交付物关系不变，仅不作为图谱节点／边渲染；负责人、参与人和卡点待行动人同样只作为任务属性展示。

结构化卡点绑定到所属任务，不形成独立图谱节点。任务存在结构化卡点时直接强化该任务节点，并在任务详情中展示缺失输入、原因、待行动人、持续时间和影响。审批等待、待审核、未开始等任务生命周期状态不自动转化为预警或卡点。

### 4.3 交付物边的必要性（#173 裁决：关系类型删除）

| 必要性 | 业务含义 | 是否参与自动关键路径与互锁检测 |
|---|---|---:|
| 必要 | 缺了它下游就无法按口径开始或完成 | 是 |
| 参考 | 供下游参考，不构成阻塞 | 否 |

如果某项信息不到位就会阻止下游任务开始或完成，应将该关系的必要性定为“必要”。

双向协作不是一条无方向边，而是两条独立的有向交付物边。每个方向分别记录交付内容、必要性和就绪状态，并分别参与风险与关键路径判断；界面可将两条边成对展示。

### 4.4 关系就绪状态（裁决 #163 修订，2026-09-01）

任务来源边的就绪只看「来源任务已完成」：完成必然产生已终审生效的当前成果，语义等价；来源任务未完成时无论是否已上传文件一律未就绪。成员来源边按输入请求「已提供」判定。

| 状态 | 判定规则 | 对下游的影响 |
|---|---|---|
| 未就绪 | 来源任务尚未完成（成员来源：输入请求尚未提供） | 必要输入未满足；参考信息仅提示 |
| 已就绪 | 来源任务已完成（成员来源：输入请求已提供） | 可以满足对应输入 |
| 已逾期 | 超过时限仍未就绪（#174：任务来源按上游任务截止日期，成员来源按录入的期望时间） | 在未就绪基础上增加逾期风险 |

候选交付物不提前替换当前交付物。终审通过后候选内容覆盖对应当前内容，被覆盖旧文件永久删除；退回后候选文件删除，原当前内容保持不变。边不再挂具体交付物项；边详情与关系列表展示来源任务的全部当前文件。

## 5. 页面结构

页面由顶部控制区、主内容区、画布控制区和右侧详情面板组成。

### 5.1 顶部控制区

顶部控制区使用单行布局：

- 左侧依次放置关键词搜索、O、KR、人员筛选和“显示已完成任务”开关；
- 右侧放置“图谱／列表”视图切换；切换文案不重复“关系”二字；
- “全局展开”放在页面标题区，不与搜索筛选混排。

返回上一级、缩放、适应屏幕和重新布局属于画布操作，放在关系图画布内。顶部不提供任务生命周期状态、风险等级、关系类型、实体类型、显示模式、布局算法、图谱导出和任意日期范围选择。

### 5.2 主内容区

- 关系图谱：承载 O／KR 层级、O 聚焦、KR 任务关系、任务聚焦和全局展开等状态。
- 关系列表：以表格查看同一份关系数据。
- 左侧风险队列：集中展示需关注的 KR，条目只显示 KR 编号与卡点数（如「KR2.1　3 个卡点」），不显示风险等级标识、任务标题、具体卡点内容或未就绪摘要；点击风险项后进入所属 KR 的任务关系层，选中风险任务并打开详情。
- 图谱与关系列表共享搜索、O／KR／人员筛选和“显示已完成任务”状态。

### 5.3 右侧详情面板

点击节点或交付物边后打开。关闭面板只取消当前选择，不自动收回已经展开的节点。

## 6. 关系图谱状态

### 6.1 默认：O／KR 层级视图

- 首屏只加载 O、KR 节点及 O → KR 层级连线，不显示任务或任务级交付物边。
- O 与下属 KR 按清晰树形结构排列；首屏不显示 KR↔KR、O↔O 或跨 O／KR 的汇总关系线。
- O → KR 层级连线只表达归属，不是协作关系，不可点击，也不打开关系详情。
- KR 节点只显示 KR 编号与名称、风险状态和卡点数量，不显示具体卡点任务、卡点原因、硬前置数、未就绪数、上下游 KR 数或其他依赖统计；正常 KR 不显示“0 卡点”。
- 红色只用于真实阻塞、高风险和依赖冲突。
- 正常 KR 使用白底和普通关系灰色描边；预警 KR 使用白底、橙色描边和预警图标；高风险／卡点 KR 使用白底、红色描边和高风险／卡点图标。
- 风险队列作为首屏风险入口；默认层级视图不为了展示预警或卡点而自动展开任务。
- 风险队列条目只显示 KR 编号与卡点数，卡点数为 0 时不显示“0 个卡点”；进入队列与排序仍由风险等级、卡点数与未就绪数共同驱动，但未就绪数不在队列中展示。

点击 O 后，只以该 O 为焦点展示其下属 KR，不展开任务。点击 KR 后进入该 KR 的任务关系层：以本 KR 全部任务为主体，同时纳入与这些任务直接相连的其他 KR 任务及真实交付物边。

### 6.2 节点聚焦与逐层展开

- 点击 O 时进入 O 层级焦点；点击 KR 时进入 KR 任务关系层；点击任务时进入对应节点焦点。
- 焦点节点在可用空间内居中或强化，显示一层直接邻居和多条关联分支。
- 点击相邻节点继续展开下一层；已经出现的节点不重复生成，只补充跨分支和闭环连线。
- 默认强化焦点和一层邻居，其他已加载内容降噪。
- 点击画布空白处取消选择，但保留当前展开结果。
- “返回上一级”遵循固定层级：任务焦点 → KR 任务关系层 → O 层级焦点 → 全项目 O／KR 层级树。通过搜索或风险队列直接进入任务焦点时，同样先返回所属 KR 的任务关系层。
- 已展开的 O／KR 节点提供明确的“收起”控制；不依赖双击或仅桌面端可用的隐藏手势。

任务的一层直接关系包括：

- 直接上游任务和直接下游任务；
- 附着在该任务上的风险等级与结构化卡点事实；
- 上述已显示节点之间的真实交付物边，包括双向和闭环边。

任务所属 O、KR、负责人和普通参与人显示在详情面板中，不为此重复生成节点；由项目成员直接提供的输入不生成成员节点或画布连线，在任务详情面板的输入源中表达（#159 裁决）。

从任务详情点击“在关系图谱中查看”时，直接进入该任务的聚焦状态，并允许继续展开完整影响路径。

### 6.3 全局展开

点击“全局展开”后：

- 展示所有 O、KR、任务及任务间交付物边；O／KR 保留为任务分组骨架，任务按所属 KR 聚拢，结构化卡点附着在所属任务上表达。
- 全局展开不生成 KR↔KR 或 O↔O 汇总关系边；协作线只连接来源任务与下游任务，项目成员直接提供的输入不绘制画布连线（#159 裁决）。
- 保留多上游、多下游、跨 KR、跨 O、双向、循环关系。
- 必要边关键路径强化显示（#173 修订）；参考边循环不进入关键路径。
- 硬依赖循环使用互锁风险样式标记。
- 卡点和高风险节点保持静态强化，不使用持续呼吸动画；新定位到的卡点可短暂提示一次。
- 采用分批布局和渲染，保证页面操作不中断。
- 点击“返回层级视图”恢复默认 O／KR 层级状态。

### 6.4 拖拽与视图控制

- 支持缩放、画布拖动、小地图和一键适应屏幕。
- 节点拖拽后，在当前浏览会话和当前展开状态内固定。
- 切换筛选或继续展开时，已固定节点尽量保持。
- “重新布局／重置视图”清除当前固定位置。
- 刷新页面、重新进入项目或其他用户访问时不继承该布局。

## 7. 搜索与筛选

### 7.1 关键词搜索

- 搜索范围包括 O、KR、任务、承担输入责任的项目成员、结构化卡点内容和交付物边名称。
- 输入时展示候选结果，不随每次输入自动改变画布。
- 选择 O 结果后进入对应 O 层级焦点；选择 KR 结果后进入对应 KR 任务关系层；选择任务结果后进入节点焦点并展开一层直接关系；选择项目成员结果后定位其承担的输入关系并打开关系详情（无成员节点，#159）；选择结构化卡点结果时定位其所属任务。
- 选择关系边结果后，高亮关系两端并打开关系详情。
- 搜索定位前的画布状态进入历史，可通过“返回上一级”恢复。
- 图谱与关系列表共用同一个搜索框与同一份搜索词：切换“图谱／列表”不清空搜索词，也不重置候选结果；页面上不出现第二个搜索输入框（§5.2）。

### 7.2 筛选条件

支持按以下条件组合筛选：

- O；
- KR；
- 人员（按任务负责人或参与人过滤任务节点，#159 后不再涉及成员节点）；
- 显示已完成任务。

“显示已完成任务”默认关闭；关闭时排除已完成任务及其关系，开启后纳入当前已完成任务和关系事实。V1 不提供独立任务状态、风险等级、关系类型或任意起止日期筛选，也不提供被覆盖旧交付文件。

### 7.3 筛选结果表达

- O、KR、人员筛选命中后，保留必要关系上下文并淡化无关节点和边。
- 筛选只改变当前视图范围，不自动切换层级或进入 KR 任务关系层。
- V1 不提供“默认淡化／仅显示命中”模式切换。
- 筛选条件变化不清除手动展开历史；重置视图时清除筛选、焦点和临时固定位置，恢复 O／KR 层级状态。

## 8. 节点与关系详情

详情面板的大标题使用 16px；正文、字段值和操作文字使用 14px；辅助说明、元信息和时间使用 12px。面板关闭按钮可用，关闭后只取消当前选择。

### 8.1 节点详情

| 节点 | 详情内容 |
|---|---|
| O | O 说明、下属 KR、总体风险和受影响范围 |
| KR | 负责人、任务数量、卡点数量和风险原因 |
| 任务（#177 裁决重做） | 按任务抽屉「任务概况」的只读版呈现：基础信息（所属 O／KR、负责人、参与人、周期、进度、量化标准、任务说明）、输入源、交付物、过程文件与外部材料、交付物接收方、当前卡点；空区块不占位；面板底部无按钮 |

项目成员无节点详情（#159 裁决）；成员提供的输入从任务详情的输入源或关系列表进入对应关系详情查看。

任务节点交互（#177 裁决）：单击显示只读概况面板；双击进入逐层展开（不再打开任务抽屉）；「查看影响路径／退出影响路径」入口移至画布操作区（选中任务时可用）。

“受影响 O／KR”仅在图谱“查看影响路径”中呈现，任务详情与节点详情面板均不展示（裁决 F1，#139；#177 面板重做后同口径）：

- 所属 O／KR 是组织层级事实，仍在任务详情页头展示。
- 受影响 O／KR 只沿下游「必要」交付物边推导（#173 修订，派生字段保留）。
- 参考输入不自动计入受影响目标。

### 8.2 关系边详情

点击具体交付物边后：

- 高亮来源节点、目标节点和当前关系。
- 展示名称、类型、必要性、提供方、接收方、计划时间和就绪状态。
- 展示当前交付物摘要以及预览／下载入口。
- 存在候选更新时只显示“有更新审核中”；候选内容不作为正式输入。
- 允许跳转来源任务或目标任务详情。
- 不提供关系编辑操作。

O → KR 层级连线不响应点击，也不打开关系详情；只有具体交付物边可以打开关系详情。项目成员直接提供输入形成的边不绘制在画布上（#159），从任务详情的输入源或关系列表进入其关系详情。

## 9. 关系列表

- 与关系图谱使用同一份关系数据和筛选状态。
- 每行展示来源任务／成员、交付物边、边类型、必要性、当前交付物状态、目标任务、提供方、接收方、就绪状态和计划日期。
- 支持搜索、筛选、排序和打开关系详情。
- 可以跳转来源任务、目标任务或在图谱中聚焦该关系。
- V1 只读，不提供新增、修改、解除或批量维护关系。

## 10. 复杂关系与关键路径

### 10.1 环形与双向关系

- 参考边允许形成循环，按真实方向渲染，但不作为硬阻塞，不进入自动关键路径（#173 修订）。
- 双向协作保存为两条独立有向边，可以成对展示。
- 画布中的同一节点只出现一次，环形和跨分支关系通过补充连线闭合。

### 10.2 硬依赖互锁（#173 修订：沿必要边）

- 系统先检测「必要」交付物边形成的循环，并标记为“互锁风险”。
- 循环内的任务和边不继续生成传统关键路径结果。
- 详情面板列出循环路径、涉及任务和当前待行动人。
- 循环外的无环必要关系继续正常计算。
- 循环解除后重新计算关键路径。

### 10.3 关键路径与降级

- 自动关键路径只基于「必要」交付物边和计划时间计算（#173 修订）；首版不引入里程碑对象。
- 计划时间完整时，结果称为“关键路径”。
- 日期不足但必要关系完整时，只展示“依赖链”，不得称为关键路径。
- 详情面板说明缺少哪些任务日期；系统不自动补日期或用推测结果代替事实。

## 11. 视觉与可用性

- O 节点使用深灰底、白色文字和无彩色描边，展示 O 编号和具体目标名称；O、KR 卡片统一使用系统第一层级灰色阴影。
- KR 节点使用白底，文字与边框保留足够内边距；正常、预警、高风险／卡点三种状态分别采用灰、橙、红描边，并以图标辅助区分。
- 节点填充和形状区分 O、KR 和任务；关系相关项目成员不作为图谱节点（#159 裁决，#146 的成员节点视觉规格随之废弃）。
- 所有任务节点统一使用实线圆环，不使用虚线区分当前 KR 内外；内外部关系由空间位置和真实连线表达。
- 普通任务使用中性灰蓝色；预警任务使用与其他模块一致的橙色（#A86917）和浅橙底（#FFF3D9）；高风险或存在结构化卡点的任务使用红色（#BD3E49）和浅红底（#FDEBED），并增加警告标识。
- 任务生命周期状态只在详情和关系列表中展示，不改变任务圆环颜色。红色只用于真实阻塞、高风险和依赖冲突。
- 当前焦点使用蓝色外层光环，不覆盖任务原有的橙色或红色风险圆环。
- #173 修订：边样式只分三类——必要输入使用灰色实线，参考输入使用灰色虚线，互锁冲突使用红色虚线并保留常驻异常标识；普通关系不常驻文字，悬停、点击或路径高亮时再显示必要性和交付物名称。
- 点击任务或关系后，其当前一层上下游影响路径临时使用蓝色粗线高亮；默认状态不使用多种蓝色、青色或线宽强调普通关系。
- 画布左下角保留紧凑图例，说明 O、KR、任务、预警、高风险／卡点、必要、参考和互锁（#173 修订）；图例不解释点击后产生的临时焦点蓝色。
- 风险、卡点、互锁、焦点和筛选结果必须能够同时区分，不能只依赖颜色。
- 支持键盘搜索、清晰焦点状态和减少动态效果的系统偏好。

## 12. 性能与异常状态

- O／KR 层级视图优先加载并始终可用。
- 聚焦模式按层加载直接关系，不一次加载整个项目。
- 全局展开采用分批布局和渲染，不阻塞页面操作。可验收阈值：首批渲染不超过 200 个节点并在此之后即可交互（缩放、拖动、返回可用），其余节点分批增量补齐；渲染期间不出现整页遮罩或输入无响应。
- 数据量较大时提示用户按 O、KR 或人员缩小范围；除上述首批渲染上限外不设置固定节点硬上限。
- 具体节点规模、响应时间、单次展开邻居数量和标签避让阈值在试点中校准。
- 没有关系数据时展示明确空态，并引导用户前往任务配置输入来源；不在本模块直接创建关系。
- 部分关系数据加载失败时保留已成功加载内容并提示重试，不将缺失数据展示为“无关系”。

## 13. 权限与只读边界

- 所有项目成员可以查看图谱、关系列表、节点和关系详情。
- 所有项目成员可以按既有权限预览／下载当前交付物。
- 本模块只展示候选更新状态，不在关系详情中展示候选内容；用户跳转任务审核 Tab 后按任务审核规则查看，候选内容不能作为正式输入。
- 本模块只提供查看、聚焦、筛选、预览／下载和页面跳转。
- 新增／修改关系、处理审核、修改日期、上报／解除卡点和发送提醒均从“全部任务”或“我的工作”完成。
- 导航和项目事实不因身份变化；权限只影响跳转后可用的业务操作。

## 14. 范围规划

### 14.1 V1（P0）

- O／KR 层级树。
- O、KR、任务节点（#159 后不含成员节点）；结构化卡点附着在所属任务上表达。
- O → KR 层级连线、任务级交付物边及关系详情；不提供 KR／O 汇总关系边。
- O 聚焦、KR 任务关系层、任务聚焦、逐层展开、全局展开和返回层级视图。
- “图谱／列表”切换。
- 左侧风险队列、搜索、O／KR／人员筛选和“显示已完成任务”开关。
- 环形、双向、跨 KR／O、硬依赖互锁、关键路径和硬依赖链降级。
- 缩放、拖动、小地图、适应屏幕、重新布局和会话内节点固定。
- 从任务详情聚焦图谱，以及从图谱跳转任务详情。

### 14.2 P1

- 关系列表批量维护；需另行明确权限、审计和关键路径重算规则。
- 跨会话保存个人画布布局。
- 在“全部任务”模块增加只读甘特视图，按 O／KR 分组展示计划时间、状态和硬前置关系；不支持拖拽改期，日期修改走任务详情直接修改（#172 修订）。

## 15. 验收标准

| 编号 | 场景 | 通过标准 |
|---|---|---|
| CR-01 | 默认进入模块 | 只显示 O、KR 和 O → KR 层级连线，不显示任务、任务级交付物边或 KR／O 汇总关系 |
| CR-02 | 层级关系 | O 与下属 KR 按树形结构清晰排列；层级线不可点击，不打开关系详情；KR 节点只显示编号与名称、风险状态和非零卡点数，不展示具体任务或原因 |
| CR-03 | 点击 O | 只聚焦该 O 及其下属 KR，不显示跨 O 汇总关系，也不展开任务 |
| CR-04 | 点击 KR | 进入该 KR 的任务关系层，显示本 KR 全部任务、与其直接相连的其他 KR 任务及真实交付物边 |
| CR-05 | 聚焦任务 | 显示直接上下游任务和一层真实任务间关系（成员输入只在任务详情面板表达，#159）；结构化卡点附着在任务节点及详情中表达，可继续逐层展开 |
| CR-06 | 返回与收起 | 返回路径遵循“任务焦点 → KR 任务关系层 → O 层级焦点 → 全项目层级树”；“返回层级视图”恢复默认状态，不依赖双击 |
| CR-07 | 全局展开 | 分批显示全部 O、KR、任务和任务间真实关系，首批不超过 200 个节点且渲染后立即可交互；O／KR 保留为分组骨架，不生成 KR／O 汇总关系边、成员节点或独立卡点节点，页面仍可缩放、拖动、筛选和返回层级视图 |
| CR-08 | 环形与双向 | 循环关系保持闭环；双向协作显示两条独立有向边 |
| CR-09 | 硬依赖循环 | 循环被标记为互锁风险，循环内不生成传统关键路径，解除后重新计算 |
| CR-10 | 关键路径降级 | 日期完整时显示关键路径；日期不足时只显示硬依赖链和缺失日期提示 |
| CR-11 | 点击关系边 | 只有任务级交付物边可点击；点击后高亮两端并打开关系详情，可查看当前交付物和跳转两端任务，不能编辑关系 |
| CR-12 | 候选更新（裁决 #163 修订） | 就绪只看来源任务是否已完成；候选内容与已上传文件不提前满足输入 |
| CR-13 | 搜索定位 | 选择节点或关系候选后正确聚焦；选择结构化卡点结果时定位所属任务，并可返回搜索前状态 |
| CR-14 | 筛选淡化 | O、KR、人员筛选保留必要上下文并淡化无关内容，不自动改变当前层级；页面不出现显示模式切换 |
| CR-15 | 已完成范围 | “显示已完成任务”默认关闭；开启后纳入已完成任务和关系，但不存在旧交付文件入口 |
| CR-16 | 卡点表达 | 层级视图通过 KR 节点和风险队列显示数量与风险摘要；任务层以红色任务节点、警告标识和任务详情表达结构化卡点、待行动人和影响路径，无独立卡点节点或持续呼吸动画 |
| CR-17 | 受影响目标 | 所属 O／KR 与沿下游必要关系推导的受影响 O／KR 分开显示（#173 修订） |
