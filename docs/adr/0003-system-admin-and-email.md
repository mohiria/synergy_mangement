# 系统管理员、邮件通道与首个管理员的产生方式

- Status: accepted
- Date: 2026-09-04

「系统设置与账号模块」PRD V1.0 引入了系统级角色、邮件外发与找回密码，本 ADR 记录其中四个跨模块的结构性决定。部署前提沿用 ADR 0001「修订：公网部署」（公有云单机、公网 IP:80、HTTP 明文），该修订中「用户管理模块的前置约束：管理员设定初始密码，首次登录强制改密」由本模块落地，两份 ADR 互相引用。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 系统管理员的项目权限 | 用户上的布尔标记；对任意项目**隐式**视同项目管理员，但**不进审批链**、不出现在成员列表、人员选择器与统计中；显式成员身份优先于隐式身份 | 管理员需要全局纠错权，但审批人必须是对结果负责的真实项目成员；隐式身份进审批链会让每个项目的终审人集合随管理员名单漂移。与「隐式访客」同一原则，权限判定与职责归属分离 |
| SMTP 密码存储 | 用环境变量提供的应用密钥 AES 加密后落库；密钥缺失时进程启动报错；读取接口永不回显 | 明文落库等于把邮箱凭据交给任何能读库的人；单机部署下环境变量是唯一比数据库更私密的位置。不用 KMS，与「无运维单机」原则一致 |
| 邮件发送形态 | 一律先写 outbox 表，由进程内后台协程取出发送，失败按退避重试若干次后标记失败；API 请求不等待 SMTP | SMTP 慢或不可达不能拖垮业务请求；outbox 让发送可重试、可观测（发送记录页读同一张表），且不引入消息队列（ADR 0001 已否决） |
| 首个管理员与应急恢复 | 由 CLI 产生（`useradd -admin`）；对已有用户设／撤走 `usermod`；不做迁移自动提权，不做「首个登录者成为管理员」 | 迁移自动提权要猜哪个用户该提，猜错就是越权；「首个登录者」在公网上等于把管理员送给最先到的人。CLI 只有能登服务器的人能跑，本身就是一道授权 |

## 被否方案

- **系统管理员进审批链**（作为兜底终审人）：会改变「终审＝项目管理员或签」的语义，且管理员名单变化会静默改写所有项目的审批人集合。
- **SMTP 密码明文落库或只存环境变量**：前者见上；后者让管理员无法在界面上改邮箱账号，与「系统设置可配置」目标冲突。
- **同步发送邮件**：SMTP 超时会让 @ 提及、任务邀请等写请求变慢甚至失败。
- **Apprise 作为邮件出口**：ADR 0001 预留的 Apprise 是通用外发适配层；本模块要的是可配置 SMTP、可测试、有发送记录，直接用 Go 标准库 SMTP 更薄。Apprise 容器保留，将来接企业微信时再用。

## 影响

- `users` 表新增系统管理员标记、邮箱（必填唯一）、停用时间戳、须改密码标记、最近登录时间；`audit_logs.project_id` 改可空以承载系统级审计。
- 新增单行系统配置表、邮件通道配置表、outbox 表、密码重置 token 表（只存哈希）。
- 权限判定入口需要在项目角色之上叠加系统管理员判断，但审批链派生与成员相关的读接口**不**读该标记。
- `.env.example` 新增应用密钥变量（名称由 #212 定）；缺失时进程拒绝启动，部署文档随之更新。
