## 0. V4.4 修订结论

### 0.1 已确认的关键决策

1. **采用三道审批关口**：任务创建入池、关键字段修改和任务完成分别进入审批；三类审批使用独立状态，避免与任务执行状态混在一起。
2. **创建入池审批**：普通成员创建或导入的任务须经所属 KR 负责人批准后进入正式任务池；KR 负责人在本人负责的 KR 下创建任务可以免审生效。
3. **关键字段修改审批**：任务标题、描述、量化指标、负责人、截止时间、输入、输入源、输出和接收方的修改须经所属 KR 负责人批准；审批期间旧值继续生效，退回则修改作废。
4. **完成审批**：任务负责人提交完成申请；配置中间审核人时采用或签，任一人通过即进入 KR 负责人终审，任一人线上退回即整体退回；未配置中间审核人时直接进入 KR 终审。
5. **最终完成确认**：KR 负责人终审通过后任务完成，本次候选交付物成为当前交付物；该终审是完成审批的最后一道关口，但不是系统内仅有的审批关口。
6. **交付物是关系图谱中的边**：任务之间的输入输出关系由交付物边连接；每项交付物首版只保留一份已审核生效的当前内容，不使用版本号或历史版本。
7. **O 就是项目目标**：一个项目可以有多个 O，每个 O 可以有多个 KR，不再额外维护重复的“项目目标”字段。
8. **概览首层收束**：默认只展示 O 和 KR；任务、负责人、进度和状态进入 KR 展开层；预警／高风险 KR 只补充一行简短原因和下钻入口。
9. **复杂关系属于首个可交付版本**：支持多上游、多下游、跨 KR、双向和循环关系，并支持循环／互锁识别。
10. **关键路径有明确边界**：自动关键路径只计算硬前置交付物边；迭代和反馈边单独表达，不参与传统关键路径计算。
11. **关系图谱可以全局展开**：默认使用纯 O／KR 层级树，用户可以主动全局展开全部任务和交付物边，再一键返回层级视图。
12. **进度不造数**：任务状态必填，百分比可选；系统不自动套用 0／50／100%。KR 进度按已填写的任务进度汇总，并显示数据覆盖度。
13. **首版提醒在系统内闭环**：使用“我的工作、站内消息和一键提醒”；企业微信、邮件等外部渠道只预留接口。
14. **首版不建设外部人员体系**：接收方默认是项目内部成员，偶发外部传递由内部协调人线下处理并记录结果。
15. **轻量成果包进入首版**：可以按项目阶段或 KR 选择当前正式成果和必要过程文件组成成果包，查看目录、来源并整包下载；成果包不得保留被后续覆盖的旧交付文件。
16. **层级与协作分层表达**：默认 O／KR 层使用树形结构表达归属；进入 KR 任务层或全局展开后，使用可承载环形、多中心和多层级交织网络的关系图谱表达任务协作。
17. **图谱按层级逐步下钻**：点击 O 只聚焦其下属 KR；点击 KR 后展示本 KR 任务及其直接关联的跨 KR 任务；点击任务或关系相关项目成员后再向外逐层展开，并保留跨分支与环形连线。
18. **任务输入支持双来源**：任务负责人可优先从系统内既有任务选择输入来源；不存在适合任务时，可以指定一名项目成员作为对接人提供输入。
19. **手动对接人一期轻量响应**：被指定成员收到站内任务通知，在“待我处理”中点击“同意接收”后承担输入提供责任；一期不增加拒绝、转派或复杂协商流程。
20. **子任务术语归一**：本次需求中的“子任务负责人”统一解释为既有三级模型中的“任务负责人”，不新增任务以下的第四层子任务。
21. **项目总览任务详情使用三 Tab**：任务详情固定为“任务概况、讨论、审核”，默认进入只读的任务概况；审核动作只对当前待行动审核人开放。
22. **任务讨论是轻量项目意见流**：所有项目内成员均可提交文字意见和 @ 成员，意见提交后不可编辑或删除，不建设附件、多层回复或独立聊天。
23. **候选内容通过后永久覆盖**：审核期间旧的当前交付物继续有效；终审通过后候选内容覆盖对应交付物项并永久删除旧文件，退回则删除候选文件，系统不保留历史文件。
24. **协作关系模块只读**：关系图谱和关系列表只承载分析、查看、预览／下载和跳转；关系维护、审核、改期、卡点处理和提醒回到任务相关页面完成。
25. **层级、聚焦和全局展开分层**：O／KR 首屏只显示 O → KR 层级线，不显示 KR／O 汇总关系边；任务协作从 KR 任务层开始展示，需要完整网络时再主动全局展开。
26. **筛选默认保留上下文**：筛选结果淡化不匹配内容，不提供显示模式切换；筛选只缩小当前范围，不自动下钻，搜索通过候选选择后聚焦，不随输入实时扰动画布。
27. **甘特图不替代关系图谱**：V1 使用关系图谱和只读关系列表；只读甘特视图作为“全部任务”P1 能力，不支持拖拽改期。

## 1. 产品定义

### 1.1 一句话定义

协同管理工具是一套围绕 O、KR、任务、输入输出关系和成果运行的项目协作系统，让所有成员在同一份项目事实中通过关系图谱看清全局、处理下一步，并始终使用唯一、已审核生效的当前成果。

### 1.2 产品模型

```text
项目
├── O 1
│   ├── KR 1
│   │   ├── 任务
│   │   ├── 输入、成果与审批
│   │   └── 上下游关系
│   └── KR 2
├── O 2
│   └── 多个 KR 与任务
├── 跨 KR／跨 O 协作关系
├── 卡点、风险与提醒
└── 成果、过程文件与成果包
```

O 本身就是项目目标。项目只维护名称、阶段、周期、项目总负责人和总推进人等基础信息，不再重复填写一段与 O 含义相同的“项目目标”。

### 1.3 需要解决的问题

- 表格能列出事项，却难以表达复杂上下游、双向和循环关系；
- 用户能看到未完成，却难以判断缺少什么输入、卡在哪个人或节点；
- 领导需要先看 O、KR 和风险，再按需下钻，不应直接面对任务蜘蛛网；
- 执行者不应为了管理重复填报状态、日报和汇报材料；
- 当前成果、候选内容、审批和过程文件不能游离在任务之外；
- 项目结束时需要形成可下载、可核验来源的阶段成果包或最终成果包。

## 2. 产品目标、原则与边界

### 2.1 首个可交付版本目标

1. 跑通 O／KR 建立、任务拆解、三道审批、交付物边协作、成果提交、KR 终审和成果归档。（V1-01）
2. 让管理者可以表格式建立或导入 OKR，并邀请 KR 负责人和执行者共同完善。（OKR-03～06）
3. 让所有项目成员查看同一份项目全局，权限只改变操作能力。（ROLE-05、ROLE-06）
4. 使用关系图谱真实记录并可视化复杂项目关系，包括环形、多中心、多层级交织、互锁和跨 KR 依赖。（TASK-04～06）
5. 让执行者主动上报卡点，系统负责带上下文提醒、影响识别和风险下钻。（WORK-06～10）
6. 让当前成果、候选内容、审批事实、过程文件和成果包统一查看，并确保项目内只存在唯一正式交付内容。（ARCH-01～05）
7. 直接使用项目事实生成今天、近 7 天、近 30 天和项目整体报告，并导出长图或 PDF。（RPT-01～04）
8. 让任务负责人优先复用系统既有任务输出作为输入，并在无匹配任务时轻量指定项目成员提供内容。（INOUT-01～03）

### 2.2 产品原则

#### 减负优先

- 一份事实只维护一次；
- 普通任务只需名称、所属 KR、负责人和时间即可提交入池审批；
- 输入、输出、交付物边和中间审核仅在实际需要时补充；
- 导入任务支持按 KR 批量提交和批量通过，减少逐条审批；
- 关键字段修改使用变更申请，审批期间不重复维护两份当前值；
- 状态由真实动作更新，系统不虚构完成百分比；
- 报告、风险和工作台从项目事实生成，不要求重复填报。

#### 全局可见，逐层理解

- 所有项目成员原则上能查看 O、KR、任务和协作关系；
- 默认从 O／KR 层级树理解项目；
- 需要时展开 KR、任务和完整关系；
- 领导、推进人和执行者看到同一份数据，只是默认关注层级不同。

#### 复杂关系完整，默认呈现克制

- 数据层完整记录复杂关系；
- 默认视图不一次铺开所有任务；
- 通过 O／KR 层级树、KR 任务关系层、节点逐层展开、筛选和局部下钻解决可读性；
- 风险必须可解释到具体任务、输入、人员或审批节点。

### 2.3 首版非目标

- 系统不承载 O／KR 的线上讨论和审批流程；O／KR 由领导层或小范围团队线下确定后录入。（OKR-06）
- 不建设绩效考核、人员排名或责任评分；
- 不建设完整即时通信、在线文档或企业网盘替代品；
- 不建设外部人员账号、外部线上审批和复杂受限分享体系；
- 不建设自由编排的复杂流程引擎；三道审批为固定产品流程；
- 不依赖 AI 自动拆任务、自动判定风险或自动润色报告；
- 不建设智能知识库、保管期限和正式档案移交；
- 首版不提供交付物历史版本、旧文件恢复或旧文件下载；
- 不管理超过 O → KR → 任务的无限子任务层级。
- 不支持三道审批之外的条件分支、会签、加签或自定义审批链。

## 3. 用户职责与权限

### 3.1 工作职责

| 职责 | 主要关注 | 主要动作 |
|---|---|---|
| 项目总负责人／领导层 | O、KR、整体关系、风险与待决策 | 查看聚合概览、全局展开、下钻、讨论和决策 |
| 总推进人 | 项目建立、拆解质量、整体进度和卡点 | 组织录入、协调、提醒、维护关系、生成报告 |
| KR 负责人 | KR 任务池质量、关键变更和最终完成 | 审批任务入池、审批关键字段修改、检查协作关系、完成终审 |
| 任务负责人 | 任务结果、输入来源和按时推进 | 补充任务、选择已有任务输入或指定对接人、更新状态／进度、提交成果、上报卡点 |
| 参与人 | 被分配的具体工作或输入提供责任 | 补充信息、同意接收输入请求、提交被授权内容／成果、报告问题 |
| 中间审核人 | 对指定完成申请做专业审核 | 在或签组中通过或线上退回 |
| 接收方 | 获取和使用成果 | 查看、下载或确认接收；不拥有审核权 |

### 3.2 系统权限

| 权限级别 | 能力边界 |
|---|---|
| 项目管理员 | 管理项目结构、成员、权限、配置和全局纠错 |
| 可编辑成员 | 在授权范围内创建和编辑 O、KR、任务与关系 |
| 普通成员 | 查看完整项目并处理本人承担的动作 |
| 只读成员 | 查看项目和参与任务讨论，不编辑任务事实或处理审核 |

### 3.3 核心权限规则

- 所有人使用相同一级导航、页面结构和项目数据；
- 工作职责决定谁能提交、审批、接收和完成终审；
- 系统权限决定谁能编辑结构和配置；
- 项目管理员不能因为管理权限自动替代中间审核人或 KR 负责人；
- 接收与审批分别配置、分别记录；
- 所有项目内成员均可查看和下载当前交付物与候选交付物，但候选内容必须标明尚未生效；
- 所有项目内成员均可提交任务讨论；讨论不改变任务事实，不属于编辑权限；
- 外部传递由内部协调人线下完成并记录，不产生外部系统账号。

| 创建成果包 | ✓ | 授权后 | 查看／下载 | 查看／下载 |
| 管理成员和权限 | ✓ | — | — | — |

## 4. 领域模型与关系规则

### 4.1 核心对象

| 对象 | 定义 | 最小字段 |
|---|---|---|
| 项目 | 组织多个 O 的协作空间 | 名称、项目负责人、状态、阶段、计划开始日期、计划完成日期 |
| O | 项目的方向性目标，可有多个 | 标题、说明、排序 |
| KR | 衡量 O 是否实现的关键结果，可有多个 | 描述、量化指标、负责人、周期、状态 |
| 任务 | KR 下最小管理单元 | 名称、所属 KR、负责人、开始／截止时间、状态 |
| 输入要求 | 任务所需的信息、材料或前置结果 | 名称、必要性、来源模式、来源任务／对接人、期望时间、就绪状态 |
| 输入请求 | 无适合来源任务时，向指定项目成员发出的轻量提供请求 | 目标任务、输入要求、指定对接人、状态、通知时间、接收时间 |
| 交付物边 | 关系图谱中连接来源节点与目标任务的边，同时表达输出、输入和协作关系 | 来源节点、目标任务、名称、类型、必要性、提供方、接收方、状态 |
| 当前交付物 | 已审核生效、当前供接收方或下游使用的唯一正式内容 | 交付物边、内容、格式、大小、提交人、生效时间、接收方 |
| 候选交付物 | 为替换当前交付物而提交、正在等待完成审核的临时内容 | 交付物边、内容、格式、大小、提交人、提交时间、审核状态 |
| 工作附件 | 不进入正式闭环的过程资料 | 文件、所属任务／KR、上传人、用途 |
| 任务讨论 | 绑定任务的项目内文字意见流 | 任务、作者、内容、被提及成员、提交时间 |
| 入池审批单 | 新任务进入正式 KR 任务池的审批事实 | 任务、提交人、KR 负责人、状态、意见、时间 |
| 关键字段变更单 | 对任务关键字段拟议值的审批事实 | 任务、旧值、拟议值、提交人、KR 负责人、状态、意见、时间 |
| 完成申请 | 任务负责人基于本次一个或多个候选交付物提出的完成请求 | 任务、候选交付物列表、提交人、中间审核组、KR 负责人、状态、时间 |
| 中间审核组 | 完成申请上的可选或签节点 | 审核人列表、状态、首个有效动作人、意见、时间 |
| 接收记录 | 内部接收方取得当前交付物的事实 | 接收方、当前交付物、时间 |
| 卡点 | 阻止任务正常推进的异常事实 | 类型、缺失输入、原因、待行动人、影响 |
| 归档记录 | 当前成果和过程文件的来源信息 | 所属 O／KR／任务、人员、时间、背景 |
| 成果包 | 某阶段或 KR 的当前成果集合 | 名称、范围、负责人、形成时间、目录 |

### 4.2 图谱节点与展开规则

关系图谱使用以下节点：

| 节点类型 | 用途 | 主要详情 |
|---|---|---|
| O | 表达目标范围 | 下属 KR、总体风险 |
| KR | 组织一组任务 | 负责人、任务数量、卡点数量和风险等级 |
| 任务 | 具体协作执行单元 | 负责人、状态、上下游、输入就绪度 |
| 项目成员 | 直接参与输入或交付流转的责任方 | 职责、待提供内容、相关任务 |

展开规则：

1. 默认只加载 O、KR 和不可点击的 O → KR 层级连线；不显示 KR↔KR、O↔O 或跨 O／KR 汇总关系边。
2. 点击 O 只聚焦其下属 KR；点击 KR 后进入任务关系层，展示本 KR 全部任务及与其直接相连的其他 KR 任务。
3. 进入任务关系层后，用户选中任务或关系相关项目成员，以该节点为当前焦点向外展开一层直接邻居，可连续点击继续扩展。
4. 一个任务节点可以向外连接多条分支；同一节点已经出现在画布中时不重复创建，只补充跨分支连线。
5. 环形、双向和跨 KR／O 的任务关系保留真实闭环，不强制转换成树形结构。
6. 选中节点及一层邻居强化显示，其他节点降噪；右侧详情面板同步展示属性、输入输出、当前交付物和待行动人。结构化卡点附着在所属任务上表达，不形成独立节点。
7. 节点填充色区分对象类型；正常／预警／高风险使用边框、光环或状态标记表达，避免与节点类型颜色混淆。

### 4.3 交付物边类型

| 类型 | 含义 | 是否参与关键路径 |
|---|---|---:|
| 硬前置交付 | 下游必须取得该交付物后才能开始或完成 | 是 |
| 信息输入 | 下游需要上游提供信息，可配置为必要或参考 | 否 |
| 正式成果接收 | 上游交付物正式交给内部接收方或下游任务 | 否 |
| 迭代／反馈 | 两项工作之间通过交付物发生多轮往返 | 否 |

关系图谱的数据表达统一为：

```text
来源任务节点／项目成员节点
→ 交付物边（名称、类型、提供方、接收方、状态）
→ 下游任务节点
```

具体文件或文本内容不单独成为关系节点，而是作为当前交付物或审核中的候选交付物关联到该边。没有文件的条件或信息仍可建立结构化交付物边。

如果某项信息不到位会阻止下游任务开始或完成，应把该方向定义为“硬前置交付”，而不是普通信息输入。双向协作是两条边形成的组合关系，必须保存为两条独立有向边；每个方向按其实际边类型分别记录交付内容、状态并参与风险和关键路径判断。

### 4.4 复杂关系与输入来源规则

1. 一个 O 包含多个 KR，一个 KR 包含多个任务。
2. 一个任务可以通过多条交付物边连接多个输入、输出、上游和下游。（TASK-03、TASK-04）
3. 支持并行任务、跨 KR、跨 O、双向和循环关系。（TASK-05）
4. 硬前置交付物边为有向边；系统识别这类边形成的循环并标记为“互锁风险”。
5. 迭代和反馈边可以形成循环，但不作为硬阻塞，也不进入传统关键路径计算。
6. 自动关键路径仅基于硬前置交付物边、计划时间和里程碑计算。
7. 必要输入未到时任务显示“等待输入”；参考输入未到只提示。
8. 只有完成终审通过后的当前交付物才能把对应交付物边标记为正式就绪，并满足下游必要输入；候选交付物不能满足下游输入。
9. 上游变化时系统计算直接影响和潜在影响，但不自动修改下游日期。（TASK-14）
10. 重要外部材料由内部协调人收集并归档。（TASK-12）
11. 任务负责人配置输入时，来源模式必须在“已有任务”和“指定项目成员”中二选一。（INOUT-01）
12. 选择“已有任务”时，系统搜索并选择具体来源任务及其交付物边；只有对应的当前交付物已生效才能满足必要输入。（INOUT-01）
13. 选择“指定项目成员”时，系统建立“成员节点 → 目标任务节点”的交付物边，并生成输入请求和站内通知。（INOUT-02）
14. 手动指定的项目成员点击“同意接收”后成为该边的提供方；同意接收只表示承担责任，不代表输入已经就绪。（INOUT-03）
15. 指定成员提交对应内容或文件后，输入请求变为已提供，目标任务输入才更新为已就绪。（INOUT-03）
16. 一期输入请求状态仅为待接收、已接收、已提供；不提供拒绝、转派或多人协商。（INOUT-03）

## 5. 状态与进度模型

### 5.1 任务生命周期状态（页面汇总）

| 状态 | 定义 | 触发动作 |
|---|---|---|
| 草稿 | 任务已建立但尚未提交入池 | 创建任务 |
| 待入池审批 | 已提交所属 KR 负责人审批，尚未进入正式任务池 | 提交入池 |
| 未开始 | 入池审批通过，尚未开始 | KR 负责人通过／免审生效 |
| 等待输入 | 必要输入尚未满足 | 系统检查依赖 |
| 进行中 | 负责人已开始执行 | 点击开始／更新状态 |
| 待中间审核 | 已提交完成申请，等待可选的中间审核或签 | 提交完成申请 |
| 待 KR 终审 | 未配置中间审核人，或任一中间审核人已通过 | 提交完成申请／中间审核通过 |
| 已完成 | 所属 KR 负责人终审通过 | KR 负责人终审通过 |
| 已取消 | 任务不再执行并保留原因 | 有权限人员取消 |

页面主状态是对生命周期的汇总显示；入池、关键字段修改和完成审批的原始状态分别记录在三类审批单中。入池审批退回后，任务回到“草稿”；中间审核或 KR 终审退回后，本次候选交付物删除，任务回到“进行中”，负责人准备新内容后重新提交完整完成审批。关键字段修改审批不改变任务生命周期状态，审批期间旧值继续生效。

### 5.2 三道审批状态

#### A. 创建入池审批

| 状态 | 含义 |
|---|---|
| 未提交 | 任务仍为草稿 |
| 待审批 | 等待所属 KR 负责人处理 |
| 已通过 | 任务进入正式任务池并变为未开始 |
| 已退回 | 任务回到草稿，可修改后重新提交 |

- 普通成员创建和导入的任务均须入池审批；
- 导入任务支持按 KR 批量提交、批量通过或批量退回；
- KR 负责人在本人负责的 KR 下创建任务免审，保存后直接进入未开始；
- 入池审批不等于任务完成终审。

#### B. 关键字段修改审批

关键字段包括：标题、描述、量化指标、任务负责人、截止时间、输入、输入源、输出和接收方。

| 状态 | 含义 |
|---|---|
| 无申请 | 当前没有待处理修改 |
| 待审批 | 拟议值等待所属 KR 负责人处理，旧值继续生效 |
| 已通过 | 拟议值成为当前值并记录审计 |
| 已退回 | 拟议值作废，旧值保持不变 |

- 中间审核人配置不属于关键字段，可直接调整并留痕；
- KR 负责人修改本人负责 KR 下的任务关键字段免审并即时生效；
- 待审批修改不暂停任务执行，也不单独构成卡点。

#### C. 任务完成审批

| 状态 | 含义 |
|---|---|
| 未提交 | 尚未提出完成申请 |
| 中间审核中 | 已配置中间审核人，等待或签结果 |
| 待 KR 终审 | 无中间审核人，或任一中间审核人已经通过 |
| 已退回 | 任一中间审核人或 KR 负责人已在线退回 |
| 已通过 | KR 负责人终审通过，任务完成 |

### 5.3 当前交付物与候选交付物状态

| 对象 | 状态 | 定义 |
|---|---|---|
| 当前交付物 | 已生效 | 已经 KR 负责人终审通过，可供接收方和下游正式使用 |
| 候选交付物 | 中间审核中 | 已随完成申请提交，等待可选中间审核或签 |
| 候选交付物 | 待 KR 终审 | 未配置中间审核人，或中间审核或签已通过，等待 KR 负责人终审 |

- 一个交付物项在审核期间可以同时存在一份当前交付物和一份候选交付物；当前交付物继续有效。
- KR 负责人终审通过后，候选交付物成为新的当前交付物，被覆盖的旧文件永久删除。
- 中间审核人或 KR 负责人退回后，候选交付物删除，原当前交付物保持不变。
- 系统不创建“已退回版本”或“历史版本”，也不提供版本号、旧文件恢复或旧文件下载。

### 5.4 中间审核或签规则

- 中间审核不是所有任务的必填流程；
- 创建人可以在创建任务时选择，也可以在提交完成申请前补充；
- 支持 0～多名中间审核人；
- 多人采用或签：任一人首先点击“通过”，完成申请即进入待 KR 终审，其余人的待办自动关闭；
- 任一人在或签尚未结束前点击“退回”，完成申请整体退回，其余人的待办自动关闭；
- 通过与退回均需记录处理人、时间和意见；退回意见必填；
- 被退回后候选交付物删除，任务回到进行中，负责人准备新内容并重新提交完整完成审批；
- 未配置中间审核人时，提交完成申请后直接进入待 KR 终审。

### 5.5 输入请求状态

| 状态 | 含义 | 触发动作 |
|---|---|---|
| 待接收 | 已指定项目成员并发送站内通知 | 创建或批准输入来源配置 |
| 已接收 | 指定成员已经点击“同意接收”，承诺提供内容 | 同意接收 |
| 已提供 | 指定成员已经提交对应内容或文件，目标任务输入更新为就绪 | 提交输入内容 |

- “同意接收”不等于输入已经提供，也不自动解除等待输入状态；
- 一期页面不出现拒绝、转派或多人协商按钮；
- 已入池任务更换来源任务或指定对接人，属于输入关键字段修改，仍执行关键字段修改审批。

### 5.6 进度规则

- 任务状态必填；
- 任务进度百分比为可选字段，由任务负责人填写真实情况；
- 系统不自动将未开始、进行中、已完成映射为 0／50／100%；
- 未填写百分比时，页面只展示任务状态，不显示推测值；
- KR 展开层可以汇总已填写任务的进度，默认任务等权；
- 项目管理员可以为关键任务设置权重；
- KR 汇总必须同时显示“进度数据覆盖度”，例如“8／12 个任务已填写进度”，避免局部数据被误解为完整进度。

### 5.7 风险表达

风险视觉等级统一为：

| 等级 | 视觉 | 含义 |
|---|---|---|
| 正常 | 中性／绿色 | 当前没有已知阻塞或临期风险 |
| 预警 | 黄色 | 临期、等待输入或存在潜在影响 |
| 高风险 | 红色 | 已阻塞、已超期、硬依赖互锁或影响关键路径 |

等待输入、审批等待、循环互锁等仍是具体事实；风险等级只是这些事实在总览和关系图谱中的视觉汇总。

## 7. 页面与功能设计

### 7.1 项目总览

#### 默认首层

- 页面顶部：项目名称、状态、阶段、计划周期和项目负责人；
- 页头不提供“创建任务”，关系入口统一命名为“查看协作全景”；
- 项目总览不设置右侧“当前待行动”侧栏，个人行动统一进入“我的工作”；
- 页面主体：多个 O，以及每个 O 下的多个 KR；
- 首层不展示独立项目目标、量化指标、任务、负责人、进度数字或风险详情；
- O 标题右侧只显示“X 个 KR”；
- KR 使用状态颜色表达正常、预警或高风险，状态标签宽度随文字收紧；
- 预警／高风险 KR 在标题下显示一行简短卡点或风险原因，不展开任务详情或独立风险卡片；
- 点击颜色或 KR 进入下钻，不在首层堆叠风险卡片。（PRJ-01、PRJ-08、PRJ-09）

#### KR 展开层

展开 KR 后展示：

- KR 负责人、周期和量化指标；
- KR 状态、可用的进度汇总和进度覆盖度；
- 任务列表、任务负责人、任务状态和可选进度；
- 关键输入、输出和直接上下游 KR；
- 风险依据和下钻入口。

负责人、周期和量化指标使用普通元信息样式，不使用强调底色。

#### 风险下钻

```text
KR 风险颜色
→ KR 风险摘要
→ 具体任务
→ 缺失输入／卡点／审批节点
→ 当前待行动人和影响链
```

### 7.2 OKR 建立与拆解

- O、KR 由领导层或小范围团队线下确定后录入，系统不承载其讨论审批；
- “新增 O／KR”打开高密度表格式弹窗，横向区分 O、KR、所属 O、负责人和周期，纵向连续添加 O 行或 KR 行；
- 支持连续新增、复制、粘贴和排序 O／KR；
- 导入弹窗提供真实文件选择区、字段映射和导入预览；未选择文件时不能确认导入；
- 导入后生成 O／KR／任务结构草稿，任务按 KR 批量提交入池审批；
- 取消全局“编辑”按钮和行内编辑／删除图标；有权限的主推进人点击 O 或 KR 行后打开右侧编辑抽屉；
- 负责人字段支持按姓名、角色或团队匹配现有项目成员，不要求用户输入内部 ID；
- KR 周期使用开始日期和截止日期选择器；
- KR 层只维护描述、量化指标、负责人、周期和状态；
- 输入、输出、审批和详细依赖进入任务层；
- 创建 KR 后可以指定负责人并邀请其继续拆任务。（OKR-03～09）

### 7.3 全部任务

- 默认按 O／KR 分组的层级列表；
- 支持折叠、展开、搜索和按 KR、负责人、状态、日期、风险筛选；
- 展示任务名称、负责人、开始／截止时间、状态、可选进度、输入就绪度、成果状态；
- 可隐藏较早已完成任务；
- “创建任务”打开高密度表格式弹窗，可连续录入所属 KR、任务名称、负责人、开始／截止日期和预期交付物；负责人支持姓名匹配，日期使用日期选择器；
- “邀请负责人完善”先选择 KR，再多选项目成员；即使该 KR 尚无任务，也可以邀请成员创建任务；
- 邀请发送后生成带 KR 和邀请说明的站内通知，受邀成员从“待我处理”进入创建任务；
- 有权限用户支持批量指派、改期和邀请完善；
- 点击任务打开任务操作详情；有权限成员可在此维护任务，项目总览中的任务详情仍保持只读概况边界；
- 普通成员创建任务后进入草稿，提交后进入待入池审批；所属 KR 负责人通过后进入“未开始”；
- KR 负责人在本人负责的 KR 下创建任务免审，保存后直接进入“未开始”；
- 支持在列表中查看并批量处理待入池任务；
- 修改关键字段时提交变更申请，页面继续显示当前生效值，并标示拟议值和审批状态。

#### 任务操作与输入来源

- “全部任务”和“我的工作”承载任务编辑、开始／更新状态、可选进度、工作附件、输入配置、候选交付物提交、完成申请发起、卡点上报和提醒等执行动作；
- 卡点从任务操作详情发起，至少填写类型、缺失输入／条件、阻塞原因和希望行动人，预计恢复时间可选；
- 任务内支持一键提醒上游负责人、指定协调人、调整计划并记录原因、升级待决策和查看影响链；解除后保留处理事实；
- 系统可识别超期、输入缺失、审批等待、硬依赖循环和关键路径影响，但不能只根据是否上传文件判定卡点，也不自动修改下游日期；
- 任务负责人配置每条输入时，来源必须在“已有任务”和“指定项目成员”中二选一；
- 选择已有任务时，支持按任务名称、O、KR、负责人和交付物名称搜索；候选项展示任务、负责人、任务状态、交付物名称和当前交付物状态，选中后自动建立“来源任务 → 目标任务”的交付物边；
- 来源任务没有已生效的当前交付物时，目标输入保持“等待输入”；当前交付物生效后自动更新为就绪；
- 没有合适来源任务时，可以指定一名项目成员作为对接人，系统建立“项目成员 → 目标任务”的交付物边并生成输入请求；
- 对接人从站内通知或“我的工作”点击“同意接收”，随后填写内容或上传文件；提交后输入才更新为已提供；
- 通知只在任务首次入池审批通过，或已入池任务的输入来源变更审批通过后发送；草稿和待审批阶段不提前打扰对接人；
- 首版不提供输入请求拒绝、转派或多人协商。

P1 在“全部任务”增加只读甘特视图，按 O／KR 分组展示计划时间、状态、里程碑和硬前置关系；不支持拖拽改期，日期修改仍走关键字段变更审批。甘特图用于查看时间安排，不替代协作关系图谱。

### 7.4 协作关系

详细交互、状态和验收规则见《[协作关系模块详细产品需求文档 V1.0](./协作关系模块_详细PRD_V1.0.md)》。本模块是只读分析视图，不提供关系编辑、审核处理、改期、卡点处理或提醒操作。

#### 默认：O／KR 层级树

- 首屏只显示 O、KR 和 O → KR 层级连线，以清晰树形结构表达目标归属；
- 不显示 KR↔KR、O↔O 或跨 O／KR 汇总关系边；层级连线不是协作关系，不可点击，也不打开关系详情；
- 每个 KR 节点只显示任务数量、卡点数量和风险等级，不显示硬前置、未就绪或上下游 KR 等依赖统计；
- 左侧风险队列集中展示需关注的 KR 和任务风险；点击风险项后直接进入所属 KR 的任务关系层，选中风险任务并打开详情；
- 点击 O 后只聚焦该 O 及其下属 KR，不直接铺开任务；
- 点击 KR 后进入该 KR 的任务关系层，展示本 KR 全部任务、与这些任务直接相连的其他 KR 任务及真实交付物边；
- 领导与所有项目成员都可以查看和下钻。

#### 节点聚焦与逐层展开

- 点击 O 时进入 O 层级焦点；点击 KR 时进入 KR 任务关系层；点击任务或直接参与关系流转的项目成员时进入对应节点焦点；
- 焦点节点在可用空间内居中或强化显示，并向外延伸多个直接关联分支；
- 点击任一相邻节点继续展开下一层，已经出现的节点只增加连线，不重复生成；
- 默认只强化焦点和一层邻居，其他节点降噪，降低复杂网络的阅读压力；
- 点击空白处保留当前展开结果；“返回上一级”依次返回“任务焦点 → KR 任务关系层 → O 层级焦点 → 全项目 O／KR 层级树”；
- 已展开 O／KR 提供明确的收起入口，不依赖双击操作；
- 任务的一层邻居包括直接上下游任务和直接输入成员；结构化卡点附着在任务节点及详情中表达，所属 O／KR、负责人和普通参与人作为详情属性展示；
- 右侧详情面板显示节点属性、所属 O／KR、负责人、输入输出、卡点、交付物边状态和当前交付物；“所属 O／KR”与沿下游硬前置关系推导的“受影响 O／KR”分开显示；
- 点击具体交付物边时高亮两端并打开只读关系详情，展示关系类型、必要性、提供／接收方、就绪状态、当前交付物及两端任务入口；
- 节点类型通过填充色区分，风险通过边框、光环或状态标记区分；普通关系线不常驻文字，悬停、选中或路径高亮时再显示关系类型和交付物名称，异常关系保留常驻标识。

#### 全局展开

页面顶部提供“全局展开”按钮。点击后：

- 在完整关系图谱画布中展示所有 O、KR、任务、关系相关项目成员及交付物边；O／KR 保留为任务分组骨架，结构化卡点附着在所属任务上表达；
- 不生成 KR↔KR 或 O↔O 汇总关系边；协作线只连接来源任务／实际输入成员与下游任务；
- 展示多上游、多下游、跨 KR、双向和循环关系；
- 硬前置关键路径加粗；
- 反馈循环保留真实闭环但不进入关键路径；硬前置循环标记为互锁风险，循环部分暂停传统关键路径计算；
- 日期不足时只展示“硬依赖链”和缺失日期提示，不宣称完整关键路径；
- 卡点与高风险节点始终静态强化，不使用持续呼吸动画；
- 支持可处理环形和多中心网络的自动排布、缩放、拖动、小地图、一键适应屏幕；
- 节点拖拽位置只在当前会话和展开状态内保持；重新布局清除固定位置，刷新或其他用户不继承；
- 支持候选式搜索，以及按 O、KR、人员筛选和“显示已完成任务”开关；搜索选择节点后按其类型进入对应层级，选择关系后高亮两端并打开详情；
- 筛选保留必要上下文并淡化不匹配内容，只改变当前范围，不自动下钻，也不提供显示模式切换；
- 不提供任务生命周期状态、风险等级、关系类型或任意起止日期筛选；“显示已完成任务”默认关闭，开启后纳入当前已完成任务和关系事实；
- 大数据量采用分批布局和渲染，必要时提示先缩小范围，不设置固定节点硬上限；
- 点击“返回层级视图”恢复默认 O／KR 层级树。

#### 关系列表

- 每行展示来源任务／成员、交付物边、边类型、必要性、当前交付物状态、目标任务、提供方、接收方、就绪状态和日期；
- 适合搜索、筛选、排序和检查，并可跳转任务或在图谱中聚焦该关系；
- 与关系图谱使用同一份关系数据和筛选状态；
- V1 只读，不提供新增、修改、解除或批量维护关系，批量维护列入 P1。

### 7.5 任务详情

从项目总览点击任务后打开右侧任务详情抽屉。页头显示任务编号和任务标题；正文固定为“任务概况、讨论、审核”三个 Tab，默认进入“任务概况”。

- “讨论 N”的 N 为累计讨论意见数；
- “审核 N”的 N 只统计当前待处理审核数；当前登录人是待行动审核人时增加醒目标记。

#### Tab 1：任务概况

任务概况是领导和项目成员查看任务事实的只读摘要，不承载任务编辑、申请发起、输入配置、内容提交或审核动作。

**基础信息**

- 固定展示任务编号、所属 O／KR、状态、负责人、参与人、开始与截止时间、可选进度、任务说明、完成标准、当前环节和待行动人。

**必要输入**

- 每项展示输入名称、来源类型、提供人、计划到达时间和就绪状态；未就绪时补充缺失原因和待行动人；
- 该区域不提供输入来源配置或内容提交动作。

**当前交付物**

- 展示全部已生效交付物，并在标题显示数量；
- 每项展示名称、内容类型／文件格式、文件大小、提交人、终审生效时间和接收方，提供预览与下载；
- PDF、图片、文本、Word、Excel 和 PowerPoint 支持在线预览；其他格式展示文件元数据并允许下载；
- 所有项目内成员均可预览和下载，首版不设置任务级文件保密权限；
- 不显示版本号、历史入口、工作附件、过程稿或候选交付物；
- 没有当前交付物时显示明确空态；如存在候选内容，补充“有更新审核中”的提示，但不把候选内容当作正式成果。

**协作关系**

- 按直接上游和直接下游展示；每条关系包含任务编号与名称、所属 KR、关系类型、关联交付物、任务负责人、任务状态和关系就绪／延迟状态；
- 点击关系可进入对方任务详情；
- 点击“在关系图谱中查看”后，以当前任务为焦点展示一层直接邻居和关系边，并可继续展开完整影响路径。

#### Tab 2：讨论

- 所有项目内成员均可查看和提交讨论意见；只有查看权限的成员也可以参与讨论；
- 首版只支持文字、@ 项目内成员和平铺时间流，不支持附件、多层回复或独立聊天会话；
- 每条意见显示作者和提交时间，提交后不可编辑、不可删除；如需纠正则追加新意见；
- 新增意见向任务负责人和被 @ 成员发送站内消息；作者不接收自己的通知，其他项目成员不因普通新增意见被广播提醒；
- 通知可直接跳回对应任务的讨论 Tab；讨论意见不改变任务状态，不等同于审核意见或操作日志。

#### Tab 3：审核

- 统一承载任务入池审核、关键字段修改审核和任务完成审核；
- 所有项目成员可查看流程和记录；只有当前待行动审核人可执行“通过／退回”；
- 项目总览不提供发起入池申请、提交关键字段变更或提交完成申请的入口；申请人从“全部任务”或“我的工作”发起；
- 当前待处理记录展开并置顶，已结束记录默认折叠；
- 每条记录展示审核类型、申请人、申请时间、申请内容、当前状态、当前待行动人和已等待时长；处理后展示处理人、处理时间、结果和意见；
- 关键字段修改审核显示修改前／修改后对比；任务完成审核显示本次候选交付物，并允许所有项目成员预览和下载；
- 候选交付物必须标注“审核中，不可作为正式输入”；只有当前待行动审核人可处理；
- 退回意见必填，通过意见选填；审核记录持续保留；
- 旧交付文件被后续内容覆盖后，早期审核记录只保留审核事实，不再提供旧文件预览或下载。

#### 当前交付物覆盖规则

- 每项交付物只保留一份当前内容；新内容在审核期间属于候选交付物，旧的当前交付物继续供接收方和下游使用；
- 同一完成申请可以包含一项或多项候选交付物，审核结果对本次申请整体生效，不允许部分通过；
- KR 负责人终审通过后，候选内容同时覆盖各自对应的当前交付物，被覆盖的旧文件永久删除；未包含在本次申请中的其他当前交付物保持不变；
- 中间审核人或 KR 负责人退回后，候选文件删除，原当前交付物保持不变；
- 系统不保留旧文件、历史版本、版本号或旧文件下载入口；审核事实记录不因文件覆盖而删除。

### 7.6 我的工作

“我的工作”页面不设置身份切换按钮；身份切换统一使用系统顶部入口，切换后只改变操作权限和个人待办，不改变项目事实。

本节为模块概要，详细规则以《我的工作模块_详细PRD_V1.0》为准；如本节与其中已经确认的模块规则冲突，应同步修正本节。

| 分组 | 内容 |
|---|---|
| 待我处理 | 本人需要补充、执行、提交的任务／输入／文件、任务创建邀请，以及等待本人同意接收或提供内容的输入请求；不混入审批事项 |
| 待我审批 | 本人需处理的入池审批、关键字段修改审批、中间审核或 KR 完成终审，卡片明确具体审核类型 |
| 待我接收 | 本人作为内部接收方需要确认的成果 |
| 等待他人 | 因上游、前序审批或决策而等待的事项 |
| 与我相关的卡点 | 与本人任务或负责 KR 相关的阻塞事项 |

每项必须说明为什么轮到我、需要什么输入、完成后影响谁。卡片只提供“去处理／查看详情”和允许直接执行的提醒；通过／退回、确认接收、同意接收和提交内容等改变业务状态的动作，统一进入任务详情完成。

任务详情固定为“任务概况／审核／讨论”三个 Tab：待我审批进入“审核”，其他分组进入“任务概况”并定位当前关注内容。输入请求卡片至少展示来源任务或目标任务、所需内容、期望时间、提出人、影响范围和当前状态；进入“任务概况”后，待接收状态提供“同意接收”，已接收状态提供“提交内容”。

只有未就绪的必要输入或硬前置进入“等待他人”，参考输入仅在任务概况提示。任务创建邀请只在通过邀请提交关联任务的入池申请，或邀请被撤回时退出。关键字段变更被退回后形成退回待处理事项，重新提交、明确放弃或任务终止后退出，单纯查看不清除。

审批超时按当前审批环节独立计时；达到项目级阈值 N×24 小时即标红并生成审批超时卡点，默认 N=3，进入新审批环节后重新计时。

### 7.7 成果、归档与成果包

关系图谱以“交付物”为边；成果与归档页统一查看每条边上的当前交付物、审核中的候选交付物、过程文件和工作附件。用户可以从任务或关系边进入当前成果，也可以从成果返回来源任务、目标任务和对应关系边。

#### 文件对象边界

| 类型 | 是否进入完成审批 | 是否可作为下游正式输入 | 是否可进入成果包 |
|---|---:|---:|---:|
| 当前交付物 | 按任务配置 | 可以 | 可以 |
| 候选交付物 | 是 | 否 | 否 |
| 过程文件 | 否 | 否 | 可以按需选择 |
| 工作附件 | 否 | 否 | 可以按需选择 |
| 重要外部材料 | 否 | 可作为输入证据 | 可以按需选择 |

#### 统一归档视角

- 按 O、KR、任务、文件类型、人员和时间筛选；
- 查看当前成果、候选内容状态、审批记录和来源任务；
- 从任务进入归档，也可以从归档返回任务；
- 记录提交人、协作者、时间和当时背景；不提供历史文件或历史版本入口。（ARCH-01～05）

#### 轻量成果包

- 按项目阶段或 KR 创建成果包；
- 从当前交付物和必要过程文件中勾选内容；
- 记录名称、范围、负责人和形成时间；
- 自动生成文件目录和来源清单；
- 支持查看来源和整包下载；
- 成果包保留逻辑清单和来源事实，但不复制或保留交付物旧文件；交付物被更新后，成果包下载使用新的当前内容；
- 首版不做保管期限、正式移交、复杂归档审批或智能知识库。

### 7.8 项目报告

- 根据 O／KR、任务状态、进度变化、成果、风险和卡点生成报告草稿；
- 时间范围使用直接点击切换：今天、近 7 天、近 30 天、项目整体；
- 默认包括 O／KR 进展、完成成果、风险卡点、待决策和下一步；
- 支持导出适合移动端阅读的长图；
- 支持导出适合正式汇报和留档的 PDF；
- 报告从同一份项目事实生成，不要求成员重复填报。

### 7.9 项目设置与审计

- 项目基础信息、阶段和周期；
- 成员、职责与系统权限；
- O／KR 结构；
- 提醒规则；
- 进度权重；
- 导入记录；
- 操作审计；
- 记录任务、交付物边、日期、进度、入池审批、变更审批、完成审核、终审、当前／候选交付物状态、卡点和成果包变化；审核事实持续保留，但被覆盖或退回的旧文件不保留。（ADMIN-01～04）

## 8. 核心业务流程

### 8.1 建立项目和 OKR

```text
新建项目
→ 填写名称、项目负责人，选填阶段和计划周期
→ 表格式建立或导入多个 O／KR
→ 指定 KR 负责人
→ 邀请拆任务
→ 普通成员创建／导入的任务按 KR 提交入池审批
→ KR 负责人批量通过后进入正式任务池
```

### 8.2 建立和执行任务

```text
创建任务最小骨架并保存为草稿
→ 可选补充输入、输出、交付物边和中间审核人
→ 提交所属 KR 负责人入池审批
→ 通过后进入未开始（KR 负责人本人创建时免审）
→ 必要输入到齐后开始执行
→ 更新状态和可选进度
```

修改标题、描述、量化指标、负责人、截止时间、输入、输入源、输出或接收方时：

```text
提交关键字段变更申请
→ 旧值继续生效，任务正常推进
→ 所属 KR 负责人通过：拟议值生效
→ 所属 KR 负责人退回：拟议值作废，旧值保持不变
```

#### 输入来源流程

已有任务来源：

```text
新增输入要求
→ 默认搜索系统内已有任务
→ 选择来源任务及对应交付物
→ 自动建立“来源任务 → 目标任务”的交付物边
→ 等待来源任务的当前交付物完成终审并生效
→ 目标任务输入自动更新为就绪
```

手动对接人来源：

```text
系统内没有合适来源任务
→ 选择“指定项目成员提供”
→ 选择对接人并填写所需内容和期望时间
→ 入池审批或关键字段变更审批通过后发送站内通知
→ 对接人点击“同意接收”
→ 对接人填写内容或上传文件
→ 输入请求变为已提供，目标任务输入更新为就绪
```

手动对接人提供的是轻量输入内容，不自动创建新任务，也不单独进入任务完成三道审批。

### 8.3 提交、审核和完成终审

```text
任务负责人提交一项或多项候选交付物和完成申请
→ 未配置中间审核：直接待 KR 终审
→ 已配置中间审核：进入多人或签
→ 任一人通过：进入待 KR 终审，其余审核待办关闭
→ 任一人退回：整体退回，删除本次候选文件，原当前交付物保持不变
→ KR 负责人终审通过：本次候选内容同时覆盖对应当前交付物，旧文件永久删除，任务完成
→ KR 负责人终审退回：删除本次候选文件，任务回到进行中，原当前交付物保持不变
→ 下游必要输入满足并收到提醒
```

同一完成申请不允许部分通过；未包含在申请中的其他当前交付物不受影响。

### 8.4 在任务中处理卡点

```text
执行者主动上报或系统识别风险
→ 填写缺失输入和阻塞原因
→ 查看直接与潜在影响
→ 一键提醒上游／指定协调人／升级决策
→ 解除卡点
→ 更新总览、关系图谱、工作台和报告
```

### 8.5 形成成果包与报告

```text
阶段或 KR 达到成果条件
→ 勾选当前交付物和必要过程文件
→ 生成成果包目录与来源清单
→ 查看来源或整包下载
→ 同期生成项目报告
→ 导出长图或 PDF
```

成果包不复制交付物旧文件；交付物被覆盖后，成果包中的对应项解析为新的当前内容。

- 任务进度百分比；
- 参与人；

- 中间审核人；
- 复杂关系类型；
- 预计恢复时间；

- 任务初始草稿状态及三道审批状态；

- 手动对接人的输入请求、站内通知和当前待行动人；
- 输入就绪状态；
- 当前待行动人；
- 进度覆盖度；
- 循环／互锁风险；
- 硬依赖关键路径；
- 卡点持续时间和影响范围；

## 10. 非功能与体验要求

### 10.1 可用性

- 桌面端为主要工作环境；V1 只保证桌面浏览器，移动端页面适配整体延后至 P1（V4.4.1 修订）；项目报告长图仍可在移动端查看；
- 高频编辑使用表格、批量操作和右侧详情；
- 关系图谱支持键盘搜索、节点聚焦、逐层展开、缩放、拖动、小地图和适应屏幕；
- 所有状态同时提供文字，不只依靠颜色。

### 10.2 性能

- 项目总览首层快速显示 O／KR；
- 全部任务支持至少 500 条任务的虚拟滚动或分页；
- O／KR 层级树优先加载；
- 全局展开图谱分批布局和渲染，不阻塞页面操作；
- 搜索、筛选和风险下钻不重新加载整个项目。

### 10.3 视觉

- 使用专业、克制、清晰的低噪声工作台；
- 首层避免大面积指标卡和字段堆叠；
- 红色只用于高风险、真实阻塞和依赖冲突；
- 页面、弹窗、抽屉、通知、审核和审计统一显示项目成员中文姓名；P01／P02 等内部 ID 只用于数据关联，不直接展示给用户；
- 全站使用 `system-ui, PingFang SC, Segoe UI, Microsoft YaHei, sans-serif`。
- 关系图谱借鉴参考视频的“多中心节点簇、向外分支、有向箭头、节点选择和右侧属性面板”结构，不照搬其品牌、业务数据或三维模型区域；
- 一期只实现二维关系图谱；节点类型颜色与风险状态颜色分层表达，并处理标签遮挡和连线交叉。

### 10.4 审计与隐私

- 关键结构、人员、日期、关系、审批、闭环、当前成果和成果包变化均留痕；
- 审核事实和来源记录不可静默删除；交付文件按已确认覆盖规则永久替换，不保留旧文件副本；
- 导出遵循项目权限；
- 原型与测试不得使用真实敏感项目数据。

## 13. 成功指标

### 13.1 清晰度

- 用户 30 秒内识别项目包含的 O 和 KR；
- 用户展开 KR 后 30 秒内识别任务、负责人、状态和风险依据；
- 领导可以在 O／KR 层级树、KR 任务关系层和全局展开图谱之间切换；
- 用户选中任一节点后，可以连续展开上下游分支并识别环形或跨簇连接；
- 用户 30 秒内找到某卡点的当前待行动人和影响链。

### 13.2 减负

- 创建普通任务不需要填写输入、输出或自定义审批流；
- 导入任务支持按 KR 批量入池审批，避免逐条操作；
- 关键字段修改审批期间旧值继续生效，任务不因变更申请停止；
- 不要求任务负责人重复填写系统可知状态；
- 不虚构任务进度；
- 一键提醒自动携带上下文；
- 输入来源优先复用已有任务；无匹配时只生成轻量输入请求，不强制增加任务；
- 报告和成果包复用已有项目事实。

### 13.3 闭环

- 每个正式任务都有入池审批或 KR 负责人本人创建免审记录；
- 每次关键字段修改都有通过／退回记录和生效前后值；
- 每个已完成任务都有 KR 负责人完成终审记录；
- 配置中间审核的任务保留或签首个有效动作及意见；
- 已生效的当前交付物能够满足下游必要输入，候选交付物不能提前满足输入；
- 成果包可以核验到当前交付物、任务、关系边和 KR，且不保留被覆盖的旧交付文件；
- 每个手动对接人输入请求都可追溯到指定人、接收时间、提交内容和目标任务。

## 16. V4.4 当前判断

```text
线下确定多个 O／KR
→ 系统内批量录入并邀请拆任务
→ 普通成员创建／导入任务，经 KR 负责人审批入池
→ 关键字段修改经 KR 负责人审批，期间旧值继续生效
→ 任务负责人优先选择已有任务作为输入来源
→ 无合适任务时指定项目成员，对接人同意接收并提供内容
→ 任务通过交付物边形成复杂关系
→ 关系图谱默认显示 O／KR 层级树，点击 KR 后查看任务关系，也可主动全局展开
→ 执行者主动上报卡点，系统带上下文推动
→ 提交候选交付物和完成申请
→ 可选中间审核人或签通过／线上退回
→ KR 负责人完成终审通过／退回
→ 通过则候选内容覆盖当前交付物并永久删除旧文件，退回则删除候选文件
→ 当前交付物推动下游
→ 形成基于当前内容的成果包和项目报告
```

V4.4 在保留关系图谱、双来源输入和三道审批的基础上，明确项目总览任务详情的领导查看、项目讨论和审核处理边界，并用“当前交付物／候选交付物”替代历史版本模型。每项交付物只有一份正式当前内容，审核通过后永久覆盖旧文件。

## 17. V4.4 变更边界

### 17.1 本版改变

1. 项目总览任务详情改为“任务概况、讨论、审核”三个 Tab，并明确各自的信息和动作边界。
2. 所有项目内成员可以提交任务文字讨论；意见不可编辑或删除，通知任务负责人和被 @ 成员。
3. 审核 Tab 统一展示入池、关键字段修改和任务完成审核，只有当前待行动审核人可以处理。
4. 交付物从多版本追溯改为每项只保留一份当前内容；审核期间使用临时候选内容。
5. 完成申请整体通过或退回；通过后覆盖对应当前交付物并永久删除旧文件，退回后删除候选文件。
6. 项目总览、OKR 管理、全部任务和“我的工作”同步已确认的 V4.4 页面交互差异。
7. 删除“卡点与风险”独立一级模块，相关能力按使用场景分散到任务、我的工作、项目总览／关系图谱和项目报告。

### 17.2 本版保持不变

- O → KR → 任务三级模型；
- 项目总览默认只展示 O、KR、风险颜色和预警／高风险的一行原因；
- 所有成员查看同一项目事实，权限只改变操作能力；
- 任务创建入池、关键字段修改和任务完成三道审批；
- 中间审核或签、线上退回和 KR 负责人终审；
- 交付物继续作为关系边；
- 执行者主动上报卡点和一键提醒上游；
- 复杂关系、循环／互锁和关键路径；
- 成果归档、成果包、项目报告和导出；
- 不根据是否上传文件自动判定卡点；
- 不扩展为可自由编排的审批流程引擎。
