# 协同管理工具领域词汇

本文件定义“综合项目协作与推进”产品中的统一业务语言，避免需求、原型和研发使用同一词语表达不同概念。

## Language

**任务生命周期状态**：
任务此刻所处的生命周期汇总状态，九值枚举：草稿（draft）、待入池审批（pending_pool_review）、未开始（not_started）、等待输入（waiting_input）、进行中（in_progress）、待中间审核（pending_intermediate_review）、待 KR 终审（pending_final_review）、已完成（completed）、已取消（cancelled）。它是页面主状态的汇总显示；入池、关键字段修改和完成审批的原始状态分别记录在对应审批单中。等待输入只在“未开始”上叠加，任务开始后不再派生。已取消须经所属 KR 负责人审批（KR 负责人在本人 KR 下免审），不是即时动作。API 字段用 status。
_Avoid_: 审批单状态、风险等级、项目状态

**入池审批单**：
新任务进入正式 KR 任务池的审批事实，由所属 KR 负责人处理；同一任务被退回后重新提交会生成新的审批单，旧单保留。KR 负责人在本人负责的 KR 下创建任务免审，系统自动生成一条已通过并标记免审的审批单以记录免审原因。API 用 poolReview，状态取值 pending／approved／rejected（待审批／已通过／已退回，未提交即无审批单），免审标记用 exempt。
_Avoid_: 完成审批、关键字段变更单、任务状态

**任务进度**：
任务负责人按真实情况填写的可选百分比（0～100）；系统不把未开始、进行中映射为百分比，未填写时页面只展示状态。完成终审通过时进度自动置为 100 并锁定编辑——任务只有一个进度事实，完成即 100%。参与 KR 汇总时未填写按 0 计。API 字段用 progress，未填为空。
_Avoid_: 状态推导进度、默认 0／50%、已完成仍按填写值计

**进度数据覆盖度**：
KR 层汇总进度时必须一同展示的事实：已入池且未取消的任务中有多少已填写进度（如「8／12 个任务已填写进度」）。汇总平均值的分母是全部非“已取消”任务、任务等权，未填写按 0 计入；已取消任务不进分子也不进分母。覆盖度用于说明这个平均值里有多少来自真实填写。系统不设任务等级与关键任务权重。API 用 progressSummary（totalTasks／filledTasks／averageProgress）。
_Avoid_: 完整进度、KR 完成率、任务权重、只统计已填写任务

**任务概况**：
面向项目整体查看场景的任务只读摘要，包含任务事实、当前交付物和协作上下文；不承载编辑、审批或状态变更。存在候选交付物时只提示有更新正在审核，不把候选内容展示为正式成果。
_Avoid_: 任务编辑面板、任务操作台

**任务基础信息**：
用于识别任务归属、责任、计划和当前推进事实的只读信息。任务详情标题区显示任务编号与名称、所属 O／KR 和更新时间；正文基础信息按负责人、参与人、周期、执行状态、进度、可选任务说明、量化标准排列。空字段和无业务事实的区块不显示。
_Avoid_: 必要输入、交付物、协作关系、任务编辑表单

**任务动态**：
任务上已经发生、不可撤销的业务事实按时间倒序留痕的只追加记录；覆盖三道审批的提交与处理、关键字段变更的生效与放弃，以及结构化卡点的出现与解除。退回类动态带上一句话理由。它只记录不派生，不参与任何状态计算，也不可编辑或删除；讨论意见不进任务动态。API 用 activity，类型用 kind，发生时间用 occurredAt，系统派生事件没有行动人。口径见 `adr/0002-task-activity.md`。
_Avoid_: 操作日志、任务讨论、审核记录、通知

**任务讨论**：
绑定到具体任务、供所有项目内成员发表文字意见并 @ 项目内成员的平铺协作记录；只有查看权限的成员也可以参与，意见提交后不可编辑或删除，纠正时追加新意见。新增意见只通知任务负责人和被 @ 的成员；它不支持附件、多层回复或独立聊天会话，不等同于审批意见，也不直接改变任务状态。API 用 discussion，被 @ 成员用 mentionUserIds。
_Avoid_: 审批意见、操作日志、群聊、讨论线程

**站内通知**：
系统向具体成员推送的定向消息事实（如讨论提及、任务创建邀请、输入请求），带来源上下文并可直达对应页面；它不改变业务状态，也不替代「我的工作」的行动分组。API 用 notification，已读用 readAt。
_Avoid_: 我的工作事项、广播公告、审批单

**任务审核**：
对任务入池、关键字段修改或任务完成申请进行确认或退回的业务环节。申请人负责发起，当前待行动审核人负责通过或退回，其他项目成员只查看流程和结果。
_Avoid_: 任务讨论、任务状态编辑、仅指完成审核、全员审批

**审核记录**：
任务各次审核的业务事实，记录审核类型、申请与处理相关人员及时间、申请内容、状态、等待时长、结果和意见；关键字段修改保留修改前后差异，完成审核关联本次候选交付物。审核记录持续保留；交付物被覆盖时仅删除旧交付内容，不删除相关审核记录。
_Avoid_: 交付物历史版本、讨论记录、操作日志

**交付物**：
任务向接收方或下游任务正式提供的成果关系，一个任务可以产生多项交付物。首版每项交付物只保留一份当前交付内容，不形成历史版本。API 用 deliverable（交付物项）；交付内容用 DeliverableFile，状态取值 current／candidate（当前／候选），文件存 MinIO、访问走预签名 URL。
_Avoid_: 工作附件、孤立文件、交付物历史版本

**工作附件（不纳入首版）**：
早期文档中“任务执行过程中使用、尚未作为正式成果提交审核的过程资料”这一概念，2026-08-28 裁决确认移出首版，不建表、不建端点、不出现在导航中。过程资料统一走“过程文件”。保留本条只为防止该词被重新引入。
_Avoid_: 当前交付物、候选交付物、正式成果、过程文件的别名

**当前交付物**：
已经审核生效、当前供接收方或下游任务使用的交付内容；一个任务的多项当前交付物可以同时存在，不使用版本号。更新内容在终审通过后覆盖对应交付物项，被覆盖的旧内容永久删除且不可追溯。上传选择本身不产生业务事实，提交成功后内容才可被项目成员预览和下载；任务尚无当前交付物时界面不展示该区块。
_Avoid_: 最新版本、历史版本、已选择但未提交的文件

**候选交付物**：
为替换当前交付物而提交、正在等待审核的临时交付内容；项目成员可以查看和下载，只有当前待行动审核人可以处理。它不作为正式成果或下游输入；终审通过后覆盖当前交付物，审核退回后删除，不留存为历史版本。
_Avoid_: 草稿版本、待生效版本、历史版本

**接收方**：
获取和使用任务成果的项目内成员：一至多名具体成员，或「所有项目成员」。接收方查看、下载并确认接收，不拥有审核权，不能退回。只读成员可以被指定为接收方，“确认接收”是只读成员唯一的写操作。它是任务的按需字段，配置口径与输入／输出配置一致（负责人／创建人／可编辑项目者，终态不可调整）。API 用 receiverScope（none／members／all）与 receivers（指定成员时的名单）。
_Avoid_: 审核人、中间审核组、外部人员、下游任务负责人

**待接收项**：
任务终审通过后为每位接收方生成、尚未确认的成果接收事实；「所有项目成员」按终审通过当时的项目成员逐人生成。它进入接收方的「待我接收」分组，确认后退出，不提供退回。API 用 TaskReceipt（confirmedAt 为空即待接收项）。
_Avoid_: 完成审批待办、输入请求、通知

**接收记录**：
接收方已确认取得任务当前交付物的事实，记录接收方、任务、生成时间和确认时间。它只追加不撤销，确认动作同时进任务动态。API 用 TaskReceipt（confirmedAt 非空即接收记录）。
_Avoid_: 下载记录、审核记录、操作日志

**中间审核组**：
完成申请上的可选或签节点：0～多名中间审核人，任一人首先通过即进入待 KR 终审、其余待办自动关闭，任一人退回则整体退回。中间审核人配置不属于关键字段，可直接调整；提交完成申请时快照进申请。API 用 reviewers（任务级配置）与 CompletionReview.reviewers（申请快照）。
_Avoid_: 会签、全员审批、KR 终审

**完成申请**：
任务负责人将一项或多项候选交付物提交任务完成审核的业务请求。同一申请中的候选交付物整体通过或整体退回；终审通过后同时覆盖各自对应的当前交付物，未包含的其他当前交付物保持不变。API 用 completionReview，状态取值 intermediate_review／pending_final／approved／rejected（中间审核中／待 KR 终审／已通过／已退回）；申请项快照保留交付物与文件名，文件被删除后审核记录仍在。
_Avoid_: 单项部分通过、整任务全部交付物替换

**直接协作关系**：
通过输入或交付物与当前任务直接相连的上游、下游及其责任方。每条关系用于说明对方任务及所属 KR、关系类型、关联交付物、责任人、任务状态和关系就绪情况，不包含需要经过其他任务才能到达的间接关系。
_Avoid_: 完整影响链、全部关系图谱

**协作关系摘要**：
任务详情中按直接上游、直接下游分组展示的直接协作关系集合；只展示真实存在的方向，不存在的一侧不显示，两侧均不存在时整个区块不显示。摘要不插入交付物中间节点，也不重复展示「等待当前交付物生效」等状态标签；完整路径通过跳转关系图谱查看。API 上由任务概况的 upstream／downstream 两组直接协作关系表达（派生字段，无关系时为空数组，前端按空组隐藏）。
_Avoid_: 交付物流程节点、空的上下游分组、完整影响链

**影响路径**：
当前任务的变化经由一个或多个协作关系传递到其他任务或 KR 的连续链路，可以包含直接影响和间接影响。
_Avoid_: 直接上下游、单条关系边

**当前环节**：
任务此刻所在的执行、审批或审核阶段，用于说明任务为什么处于当前状态；它是流程事实，不是处理入口。API 字段用 currentStage（中文标签，派生字段）。
_Avoid_: 任务状态、审批操作

**待行动人**：
在当前环节中需要执行下一项业务动作的项目成员，可能是任务负责人、审核人或 KR 负责人。API 字段用 pendingActorId／pendingActorName（派生字段，无待行动人时为空）。
_Avoid_: 任务负责人、参与人

**我的工作事项**：
由任务、审批单、输入请求、待接收项、结构化卡点或任务创建邀请按当前成员职责派生的个人行动或等待事实；同一业务事项只归入一个分组，但同一任务可以因不同业务事实出现在多个分组。API 用 workItem，五个分组为 pending／approvals／receipts／waiting／blockers（待我处理／待我审批／待我接收／等待他人／与我相关的卡点）。
_Avoid_: 新建待办记录、任务副本、通知消息

**任务创建邀请**：
KR 负责人或项目管理员邀请指定成员在某个 KR 下创建任务的行动请求；受邀人通过该邀请提交关联任务的入池申请，或邀请被撤回时结束，同一 KR 下无关任务不会使其结束。API 用 taskInvite，状态取值 pending／completed／revoked（待处理／已完成／已撤回）。
_Avoid_: 任务指派、已创建任务、普通通知

**关键字段变更单**：
对任务关键字段拟议值的审批事实：保留修改前后差异、修改原因与审批意见；审批期间旧值继续生效，通过后拟议值成为当前值，退回后拟议值作废。任务取消复用同一张单据，作为一种变更类型记录（变更字段＝任务状态，拟议值＝已取消，原因必填），不另设第四道审批。API 用 fieldChange，状态取值 pending／approved／rejected；一个任务同时最多一张待审批变更单，且待审批取消单与入池审批单、完成申请互斥——任务上有任一未决审批单时不能发起取消，取消审批期间也不能提交其他单据。任务为草稿时的完善不走变更单；KR 负责人改本人 KR 下任务免审即时生效并留一张已通过变更单。
_Avoid_: 任务直接编辑、入池审批单、完成申请

**退回待处理事项**：
关键字段变更被退回后，为原提交人派生的待处理事实，保留退回理由，直到重新提交、明确放弃本次变更或任务终止；仅查看不代表处理完成。API 上表现为 rejected 且 resolved=false 的变更单；放弃或重新提交后 resolved=true。
_Avoid_: 已读通知、任务退回状态、永久提示

**审批超时**：
审批件在当前审批环节持续等待达到项目级阈值 N×24 小时的事实；N 在项目设置的“规则设置”页配置，默认 3 天，三道审批共用一个值；进入新的审批环节后重新计时，处理或关闭后解除，并形成对应的结构化卡点。
_Avoid_: 从申请最初提交时间累计、临期提醒、任务超期

**风险等级**：
用于说明任务或 KR 当前风险程度的读时派生值，统一分为正常、预警和高风险，不落库、无写入路径、任何人不能手工设置。派生口径：`风险等级 = max(该对象上全部未解除卡点的最高等级, 临期判定, 超期判定)`；超期（已过截止日期）为高风险，临期（距截止日期不足项目“临期阈值”，默认 3 天）为预警；KR 与 O 的风险等级向下取其全部下级对象的最大值。它只反映真实风险，不由未开始、等待输入、待审核或已完成等任务生命周期状态自动推导。API 字段用 riskLevel（只读派生字段），取值 normal／warning／high_risk。
_Avoid_: 任务生命周期状态、审核状态、完成进度、可写字段、risk_level 落库列

**结构化卡点**：
由结构化事实读时派生、绑定到具体任务的阻塞事实；没有人工上报，也没有手动解除，触发条件消失即自动解除。四类触发：上游未就绪（必要输入未就绪且任务尚未开始；任务一旦进入进行中即自动解除，必要输入未就绪不阻断开始、上传或提交完成申请）、任务超期（截止已过且未完成）、审批超时（审批件在当前环节等待达到 N×24 小时）、硬依赖互锁（硬前置交付物边成环）。记录缺失的输入或条件、阻塞原因、待行动人（可多人）、产生时间和影响范围，等级按事实严重度派生为预警或高风险。API 用 blocker，类型 kind 取值 upstream_unready／task_overdue／approval_timeout／interlock（上游未就绪／任务超期／审批超时／硬依赖互锁）；因不落库，寻址用合成键 key（形如 task_overdue:42），没有自增 ID 与 open／resolved 状态。
_Avoid_: 人工上报、手动解除、协调人、一般任务状态、没有事实说明的颜色标记

**提醒目标**：
一键提醒可寻址的「当前该谁动了」。它不等于结构化卡点：等待他人分组里尚未成卡点的等待——刚提交还没到审批超时阈值的审批件、待对接人提供的输入请求、尚未交付的上游任务——同样是提醒目标。卡点目标按卡点合成键寻址，等待事项按 wait:<事项类型>:<事项 ID> 寻址；提醒正文自动带入任务、缺失输入、截止时间和下游影响；冷却按（发起人、被提醒人、任务）三元组计，默认每天 1 次、阈值取项目规则设置，换一个被提醒人不受影响；待行动人不提醒自己，只读成员不可提醒。API 用 targetKey（我的工作卡片的 refKey 与卡点的 key 都可直接作为目标）。
_Avoid_: 催办工单、@ 提及、广播公告、仅指卡点提醒

**必要输入**：
任务开始或继续推进前必须获得的内容、文件或条件，其来源可以是已有任务交付物或指定项目成员。
_Avoid_: 参考资料、可选附件

**输入请求**：
无适合来源任务时向指定项目成员发出的轻量提供请求（词汇表「任务创建邀请」之外的另一种行动请求）；状态三值：待接收（pending）、已接收（accepted）、已提供（provided），不提供拒绝、转派或多人协商。通知只在任务首次入池审批通过后发送，草稿与待审批阶段不打扰对接人。API 用 inputRequest，附着在「成员 → 目标任务」的交付物边上。
_Avoid_: 任务创建邀请、审批单、普通通知

**输入就绪**：
必要输入已经满足任务使用条件；来自已有任务时须有已生效的当前交付物，来自指定成员时须已完成内容提交。
_Avoid_: 已同意接收、已上传草稿

**多选树形穿梭框**：
用于在层级数据中批量选择对象的统一界面组件。任务来源按 O／KR／任务分层，成员来源按团队／成员分层；支持搜索、选择整组或多项、左右移动和移除，各层级复选框尺寸一致。它只是选择手段，确认提交后按所选对象分别形成交付物边或输入请求等业务事实。
_Avoid_: 单选列表、平铺成员卡片、不同尺寸复选框

**交付物边**：
从来源任务或实际承担输入责任的项目成员指向下游任务的有向协作关系，记录交付物名称、关系类型、必要性、提供方、接收方和就绪状态；当前交付物与候选交付物关联在这条边上，不形成独立图谱节点。API 用 edge（DeliverableEdge），类型 edgeType 取值 hard_prerequisite／information／handover／feedback（硬前置交付／信息输入／正式成果接收／迭代反馈），必要性 necessity 取值 required／reference（必要／参考），就绪用 ready（派生字段）。
_Avoid_: 交付物节点、孤立文件节点、无方向关系

**O／KR 层级视图**：
只表达项目中 O 与下属 KR 的归属结构，不承载 KR 之间或 O 之间的任务协作关系；风险通过节点事实和风险队列表达。
_Avoid_: KR 聚合关系图、KR 汇总关系边、目标协作网络

**KR 任务关系视图**：
从某个 KR 下钻后，以该 KR 的任务为主体，并纳入与其直接相连的其他 KR 任务，通过交付物边表达真实输入输出关系。
_Avoid_: 仅展示本 KR 任务、KR 汇总关系边

**关系相关项目成员**：
直接参与输入或交付流转的项目成员，包括被指定提供输入，或尚未形成上游任务但承担交付责任的成员；卡点待行动人只作为任务风险事实展示，不因此成为关系相关项目成员。
_Avoid_: 全部项目成员、普通任务参与人、仅作为属性展示的负责人

**关系就绪状态**：
交付物边能否向下游提供正式可用输入的系统判断。只有已生效的当前交付物可以使关系就绪；候选内容不能提前满足输入，已有当前内容时的候选更新也不改变原有就绪状态。
_Avoid_: 任务生命周期状态、候选内容已提交、文件已上传

**成果包**：
某阶段或 KR 的当前成果集合：名称、范围、负责人、形成时间与目录。目录只引用交付物项，不复制文件；交付物被覆盖后成果包对应项解析为新的当前内容，整包下载时按当前内容流式打包。API 用 package（ArtifactPackage）。
_Avoid_: 历史版本快照、文件副本、归档冻结

**受影响目标**：
任务或卡点沿下游硬前置交付物边可能拖累的 KR 或 O，由系统根据真实关系推导并展示对应影响路径；它不同于任务直接归属的 O／KR。
_Avoid_: 所属目标、所有下游关系、反馈关系推测影响

**硬依赖链**：
由硬前置交付物边形成、但因任务计划时间不足而只能确认先后依赖、不能完成传统关键路径计算的关系链。首版不引入里程碑对象，关键路径只用硬前置边与计划时间。API 上表现为 criticalPathAvailable=false 时的硬前置边集合。
_Avoid_: 关键路径、普通信息输入链、反馈循环

**互锁风险**：
硬前置交付物边形成循环时的风险事实：循环内的边标记 interlockRisk=true，循环部分暂停传统关键路径计算；迭代／反馈循环不构成互锁，也不进入关键路径。API 字段用 interlockRisk／onCriticalPath（派生字段）。
_Avoid_: 反馈循环、一般依赖、死锁告警

**只读甘特视图**：
“全部任务”模块的 P1 辅助视图，按 O／KR 分组展示任务计划时间、状态和硬前置关系；不允许拖拽改期，日期修改仍通过关键字段变更审批完成。
_Avoid_: 协作关系图谱、甘特编辑器、资源排程工具

**O（目标）**：
项目的方向性目标，一个项目可以有多个；只维护标题、说明和排序，其讨论与确定在系统外完成，系统不承载 O 层审批。API 用 objective（Objective、objectiveId）。
_Avoid_: KPI、任务分组、项目阶段

**KR（关键结果）**：
衡量所属 O 是否实现的关键结果，一个 O 可以有多个；KR 层只维护描述、量化指标、负责人、周期和状态，输入、输出、审批和详细依赖进入任务层。PRD 中 KR 的「状态」即风险等级。API 用 keyResult（KeyResult），描述用 description，量化指标用 metric，状态用 riskLevel。
_Avoid_: 子目标、里程碑、任务

**KR 负责人**：
对一个 KR 的达成负责、承担该 KR 下任务入池审批、关键字段变更审批、任务取消审批与完成终审职责的项目成员。负责人不可为空：更换时必须直接指定继任者，若该 KR 下存在未决审批件则弹确认框、默认转交继任者并发站内通知；仍在担任 KR 负责人的成员不能被移出项目。它是工作职责，不是系统权限级别，不因项目管理员身份被替代——唯一例外是负责人已不再是项目成员且尚未指定继任者时，项目管理员可代其处理该 KR 下的未决审批，记录标注“项目管理员代 KR 负责人处理”。API 字段用 owner（如 KeyResult.ownerId）。
_Avoid_: 项目负责人、项目管理员、任务负责人、空负责人

**项目负责人**：
项目字段指向的唯一负责人（1 人），对项目整体结果负责；与项目管理员是两个独立角色，享有与管理员同等的权限，但不自动成为管理员。API 字段用 owner（如 ownerId）。
_Avoid_: 总负责人、总推进人、项目管理员

**项目成员**：
被加入某个项目并持有一个成员角色的内部用户；成员资格决定其在该项目内的动作权限。产品不设外部账号体系，偶发外部传递由内部协调人记录。项目负责人不必是项目成员，其权限独立于成员资格存在。API 用 member（如 ProjectMember）。
_Avoid_: 外部人员、访客、任务参与人

**成员角色**：
项目成员的系统权限级别，三值枚举：项目管理员（admin）、普通成员（member）、只读成员（viewer）；决定谁能编辑项目结构、成员与配置，不替代工作职责（如 KR 负责人的审批不因管理员身份被替代）。API 字段用 role。
_Avoid_: 工作职责、项目负责人、职位、可编辑成员

**项目状态**：
项目整体推进的系统性枚举，取值为未开始（not_started）、进行中（in_progress）、已完成（completed）、已归档（archived），由成员手工设置；与自由文本的“项目阶段”正交，不由任务或 KR 状态自动推导。
_Avoid_: 项目阶段、任务生命周期状态、进度百分比

**参与人**：
任务上除负责人以外的协作者名单，只作展示与检索：不产生待办、不进入任何审批链、不影响权限、不参与归组与排序。它是任务的按需字段，不属于关键字段，修改直接生效并留痕。API 字段用 participants。
_Avoid_: 任务负责人、接收方、中间审核人、待行动人

**对象编号**：
O、KR、任务在创建时由系统分配并持久保存的显示编号：O 用自然数（`O1`、`O2`），KR 结合所属 O（O1 下第一个 KR 为 `KR1.1`），任务结合所属 KR（KR1.1 下第一个任务为 `1.1.1`）。编号一经分配不随排序或删除重排——删除 O2 后 O3 仍是 3，保证历史记录、报告与截图中的编号长期有效。前端不按下标复算编号。API 字段用 code。
_Avoid_: 数据库自增 ID、列表下标、排序序号、可变编号

**项目规则设置**：
项目设置下的独立页面，承载按项目生效、仅项目管理员可改的阈值配置，均有默认值：审批超时阈值（默认 3 天，三道审批共用）、临期阈值（默认 3 天，指距任务截止日期的天数，用于风险等级的预警判定）、一键提醒冷却（默认同一发起人对同一被提醒人的同一任务每天 1 次）。规则不写死在代码里。API 用 projectSettings。
_Avoid_: 全局配置、成员级个性化、硬编码阈值、提醒规则（旧称）

**项目阶段**：
描述项目当前业务阶段的自由文本标签（如“联合联调阶段”），选填；成果包可按阶段圈定范围。它不是枚举，也不参与任何系统规则。
_Avoid_: 项目状态、固定阶段枚举
