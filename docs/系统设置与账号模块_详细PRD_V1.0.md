## 0. 结论

本模块把「谁能进系统、进来后叫什么、系统长什么样、消息怎么送出去」这四件事收成一个系统级层面，与项目空间正交：

- **账号由管理员分配**：无自助注册；系统管理员在「系统设置 → 用户管理」建号、设初始密码，用户首次登录强制改密；停用而非删除。
- **系统管理员**是唯一的系统级角色：隐式为所有项目的项目管理员，但不进任何审批链、不出现在成员列表与人员选择器。
- **个人中心**承接本人的资料、密码、登录安全与通知偏好；顶栏身份浮层只剩「个人中心」「登出」。
- **系统设置**四节：基本信息（品牌与访问地址）、通知设置（邮件通道与事件开关）、用户管理、操作审计。
- **邮件**是站内通知的同步渠道，不是新的通知源：系统级开关、个人偏好、账号未停用三者同时成立才发；找回密码邮件独立于这些开关。
- 全系统用户可见文案统一用「密码」，不再用「口令」。

## 1. 定位与目标

### 1.1 一句话定义

系统级的账号、身份、品牌与外发渠道管理，让一个约 100 人的团队在公网 IP:80 的单机部署上能安全地开账号、改密码、找回密码并收到邮件提醒。

### 1.2 要解决的问题

- 现状只有 CLI `useradd` 建号，没有界面、没有停用、没有找回密码；上线公网前必须有管理员可操作的账号闭环（ADR 0001 修订：上线排在本模块之后）。
- 没有系统级角色：谁来建号、谁来改品牌、谁来看系统级审计，没有权限主体。
- 品牌（名称、副标题、标志）在三处写死，不能改。
- 站内通知只能进系统看；不打开系统就不知道有人 @ 了自己。

### 1.3 目标（首版）

1. 系统管理员能在界面上完成建号、停用／启用、重置密码、改资料、设／撤管理员，每一步落系统级审计。（AC-72～AC-76）
2. 新账号与被重置的账号在改密前进不了任何业务页面。（AC-73）
3. 用户能在个人中心改显示名、邮箱、密码，查看并踢掉其他设备的会话。（AC-77、AC-78）
4. 品牌四项文字与 logo 可配置，登录页在拿到会话前就显示配置值。（AC-80、AC-81）
5. 邮件通道可配置、可测试、异步发送、失败可见；五类站内通知按开关同步成邮件；找回密码走邮件链接。（AC-82～AC-85）

### 1.4 非目标（明确不做）

记住我、验证码（CAPTCHA）、MFA、头像、邮箱验证、邮箱登录、删除用户、批量导入用户、部门／组织结构、自助注册、审批待办邮件、每日摘要、企业微信渠道、个人中心「我参与的项目」、系统设置「安全设置」空壳、HTTPS／域名（ADR 0001 修订已否决）。

## 2. 用户与角色

| 身份 | 定义 | 本模块内能做什么 |
|---|---|---|
| 系统管理员 | 用户上的系统级标记，两档：系统管理员／普通用户 | 进入系统设置四节；对任意项目视同项目管理员（§8） |
| 普通用户 | 未带该标记的登录用户 | 登录、找回密码、个人中心；看不到系统设置入口，直接访问得 403 |
| 未登录访客 | 尚无会话 | 登录页、找回密码；只能读品牌信息与「可找回密码」标志 |

首个系统管理员由 CLI 产生（`useradd -admin`）；所有管理员被撤销或停用后的应急恢复也走 CLI（`usermod`）。不做迁移自动提权，不做「首个登录者成为管理员」。

## 3. 登录页

### 3.1 内容

- 品牌区：logo（未上传时为系统名称首字）、系统名称、副标题，全部读系统设置（§7.1）；浏览器标签页标题同步。
- 表单：用户名、密码（带显示／隐藏切换）、登录按钮。
- 提示语：读系统设置「登录页提示语」，默认「账号由管理员分配」；为空则不显示该行。
- 「忘记密码」入口：仅当邮件通道已配置（品牌读取接口 `canRecoverPassword` 为真）时显示（§4）。

### 3.2 行为

- 登录用用户名 + 密码；成功后签发 HttpOnly cookie `session`，7 天滑动过期（现状不变）。
- 错误文案统一为「用户名或密码错误」，不区分账号是否存在。
- **停用账号**：只有在用户名与密码都正确时才提示「账号已停用，请联系管理员」；其余情况仍是统一文案（公网部署防枚举）。
- **限速**：现有按（用户名, IP）计数的登录失败限速不变；被限速（429）时提示「尝试过多，请 N 秒后再试」，N 取接口返回的剩余等待秒数，前端倒计时归零后可再试。
- 登录成功记录该用户「最近登录时间」（§7.3 用户列表、§6.3 登录安全消费）。
- 登录后若用户带「须改密码」标记，进入首次改密页（§5），不进任何业务页面。

### 3.3 密码输入框（全系统共用组件）

登录、首次改密、修改密码、找回密码、管理员建号与重置密码的所有密码输入框：

- 有显示／隐藏切换；
- 拦截复制与剪切事件（明文态下浏览器默认可复制，须显式拦截），保留粘贴；
- 前端提示与校验文案统一「8～32 位」，规则以后端为准。

## 4. 找回密码

### 4.1 入口与前提

- 入口只在邮件通道已配置时显示；未配置时登录页没有该入口，对应接口仍存在但返回「未开通找回密码」（前端不会调到）。
- 两个接口均免登录，均为 POST + JSON（将来 #192 同源校验不需要豁免）。

### 4.2 请求重置

- 输入用户名或邮箱。无论账号是否存在、是否停用，统一回文「若账号存在，重置邮件已发送」。
- 请求接口挂现有登录限速（按输入标识 + IP 计数），触发时 429。
- 账号存在且未停用时：生成一次性 token，**只落哈希**，30 分钟有效；同一用户的新请求作废旧 token；邮件用系统设置「访问地址」拼重置链接（`<访问地址>/reset-password?token=…`），经 outbox 发送（§10.2），不受事件开关控制。
- 请求阶段不写审计。

### 4.3 提交新密码

- 提交 token 与新密码（8～32 位，§5.2）。
- 成功：作废 token、清除「须改密码」标记、踢掉该用户全部会话、写一条系统级审计（目标用户、时间；操作者为空）；提示后回登录页。
- token 过期、已用、篡改、对应用户已停用：统一「链接无效或已过期」。

### 4.4 已知风险（接受）

重置链接经 HTTP 明文传输，与密码明文传输同级风险（ADR 0001 修订）。

## 5. 首次登录强制改密

### 5.1 标记

- 用户上有「须改密码」标记（`mustChangePassword`）。管理员建号（§7.3）与管理员重置密码（§7.3）置为真；用户自行修改密码（个人中心或首次改密页）与找回密码成功后清除。
- 当前用户接口返回该标记。

### 5.2 密码规则（与安全票 #193 共用，写在 domain 层，所有密码入口复用）

- 长度 8～32 位（按 Unicode 字符计）；同时 UTF-8 字节数不得超过 72（bcrypt 上限，超过会被静默截断），超出按同一上限文案拒绝。
- 不做弱密码黑名单、不做禁含用户名、不做字符组合要求。
- 文案：不足 8 位「密码至少 8 位」；超过上限「密码最多 32 位」。

### 5.3 拦截

- 标记为真时，后端对**除**登录、登出、修改密码、读当前用户、品牌读取以外的所有接口返回 403，错误码 `password_change_required`。
- 前端登录后拿到标记即整页显示「首次登录请设置新密码」（只有新密码、确认新密码两个框，不要求输入旧密码：初始密码是管理员设的，用户刚用它登录过），改完进入系统；直接输入其他路由一律回到该页。

## 6. 个人中心

路由 `/me`，不挂在项目下，项目壳与项目列表壳都能进；左侧分节导航复用项目设置页的 `settings-nav` 形态。顶栏身份浮层收敛为：头像首字、显示名 + 用户名、「个人中心」、「登出」；原「修改密码」按钮移除。

### 6.1 基本信息

- 用户名只读；显示名、邮箱可改。邮箱必填、全局唯一（大小写不敏感）、不能清空；重复时拒绝并提示「邮箱已被使用」。
- 改显示名后侧栏／顶栏头像首字与显示名即时更新。
- 本人改资料不写审计。

### 6.2 修改密码

- 旧密码 + 新密码 + 确认；新密码按 §5.2。
- 成功后其他会话失效（维持现状）、清除「须改密码」标记；本人改密不写审计。

### 6.3 登录安全

- 活跃会话列表：登录时间、最近活动时间、是否当前会话；最近活动时间随滑动过期刷新时一并记录。
- 「退出其他设备」：作废本人除当前会话外的全部会话。
- 显示最近登录时间。

### 6.4 通知偏好

- 总开关「邮件通知」+ 五个事件开关（§10.3），默认全开。
- 系统级已关闭的事件在本页置灰不可用，并注明「系统未启用」。
- 本页不影响站内通知，只影响是否同步邮件。

## 7. 系统设置

路由 `/system/…`，不挂在项目下；入口在两套壳的侧栏底部（原「项目设置」位置），只对系统管理员显示；非系统管理员直接访问显示 403 页，后端对应接口 403。页面采用与项目设置一致的左侧分节导航，四节顺序：基本信息、通知设置、用户管理、操作审计。

「项目设置」移到主导航「项目报告」之后成为末项（主 PRD §6 同步）。

### 7.1 基本信息

单行系统配置，字段与上限（按 Unicode 字符计，输入框显示字数与上限）：

| 字段 | 上限 | 必填 | 默认 | 用途 |
|---|---|---|---|---|
| 系统名称 | ≤10 | 是 | 协同管理工具 | 登录页、两套壳侧栏品牌区、浏览器标签页标题 |
| 副标题 | ≤16 | 否 | O／KR／任务协同推进 | 登录页、侧栏品牌区 |
| 登录页提示语 | ≤60 | 否 | 账号由管理员分配 | 登录页 |
| 访问地址 | URL | 否 | 空 | 找回密码邮件拼链接；为空时找回密码邮件用请求的 Host 兜底 |

上限依据：侧栏 224px、标题 16px 一行约 8 汉字，副标题 12px 约 11 汉字；侧栏一行放不下时省略号截断兜底。

logo：

- 仅 PNG／JPG／WebP，≤512KB，建议正方形；非正方形按居中裁切显示；不收 SVG（可内嵌脚本）。
- 文件存 MinIO，浏览器经后端接口流式读取（免登录），不给 MinIO 直链或预签名 URL（兼容 MinIO 不对外暴露）；出图 URL 带版本或 ETag，更换后浏览器能拿到新图。
- 登录页与两套壳的品牌标志位显示 logo，兼作 favicon；未上传或已删除时回退为系统名称首字，favicon 保持现有内联图标。

品牌读取接口免登录（登录页在拿到会话前就要显示），返回四项文字、logo 版本与 `canRecoverPassword`；写接口仅系统管理员，写操作自动进系统级审计。

### 7.2 通知设置

邮件通道（§10.1）配置、测试邮件、最近发送记录、系统级事件开关（§10.3）。

### 7.3 用户管理

列表列：用户名、显示名、邮箱、是否系统管理员、状态（正常／已停用）、创建时间、最近登录。

行操作与规则：

| 操作 | 规则 |
|---|---|
| 新建用户 | 用户名、显示名、邮箱、初始密码（§5.2，管理员设定）；用户名与邮箱全局唯一；新用户带「须改密码」 |
| 停用／启用 | 停用记时间戳（非空即停用）；停用后不能登录、现有会话立即全部失效；不能停用自己；不改审批逻辑，停用者若在审批链上由项目管理员按现有规则调整成员 |
| 重置密码 | 管理员设新密码（§5.2）；该用户全部会话失效并置「须改密码」 |
| 修改显示名与邮箱 | 邮箱仍必填唯一 |
| 设／撤系统管理员 | 不能撤销自己（防锁死） |

停用账号的表现：人员选择器所用的用户列表默认不返回停用用户；历史记录（负责人、审批人、成员）照常显示名字，成员列表与用户管理里加「已停用」标签；用户摘要契约带 `disabled`。

以上写操作全部进系统级审计，操作者为当前管理员；密码与初始密码不进审计摘要。

### 7.4 操作审计

只列系统级记录（项目字段为空），列与项目设置审计页一致：时间、操作者、动作、对象、摘要；分页同项目审计页。落审计的范围：用户管理各操作、基本信息与通知设置修改、找回密码成功重置；不落：个人中心改密与改资料、找回密码请求。

## 8. 系统管理员角色

- 用户上的系统级标记；`useradd -admin` 建号即标记，`usermod` 可对已有用户设／撤；界面设／撤见 §7.3。演示数据中赵文琪（user 1）为系统管理员。
- 当前用户接口返回该标记（`isSystemAdmin`）。
- **权限判定**：对任意项目视同项目管理员（可查看、编辑、进项目设置、管成员）；项目列表对其显示全部项目。
- **不进审批链**：审批人仍由真实项目成员按现有规则派生；系统管理员若被显式加为成员，按其成员角色正常参与（显式身份优先于隐式身份，与「隐式访客」同一原则）。
- **不出现在**成员列表、人员选择器、进度与统计中；隐式身份只影响权限判定。
- 以隐式身份做的项目操作照常进项目审计，操作者为本人。

## 9. 邮箱

- 用户邮箱必填、全局唯一（大小写不敏感）。存量用户迁移时回填 `<用户名>@local.invalid` 占位（`.invalid` 为保留顶级域，永不投递），管理员或本人事后改正。
- `useradd` 必填 `-email`；演示数据 15 人配 `@example.com` 邮箱。
- 不做邮箱验证，不支持邮箱登录；邮箱只用于找回密码与邮件通知。

## 10. 邮件

### 10.1 邮件通道

- 配置项：SMTP 主机、端口、加密方式（无／STARTTLS／SSL）、账号、密码、发件人显示名与地址。
- 密码用环境变量提供的应用密钥 AES 加密后落库；保存后界面只显示「已设置」不回显；读取接口不返回密码；应用密钥缺失时进程启动报错（变量名由实现票 #212 定，须进 `.env.example`）。
- 「发送测试邮件」两个选项：发到我绑定的邮箱（预填当前管理员邮箱）／发到其他邮箱（手填）。
- 「最近发送记录」：最近 50 条，列收件人、事件、状态（待发送／已发送／失败）、失败原因、重试次数。
- 配置写操作进系统级审计，密码不进摘要。

### 10.2 outbox 异步发送

- 所有邮件先写 outbox 表，由后台协程取出发送；API 请求不等待 SMTP。
- 失败按退避重试若干次后标记失败；SMTP 不可达时 API 立即返回，记录显示失败与重试次数。
- 邮件通道未配置时不写 outbox（找回密码入口此时也不显示）。

### 10.3 站内通知同步邮件

五个事件与现有站内通知 kind 一一对应，默认全开：

| 事件 | 站内通知 kind |
|---|---|
| 讨论区被 @ | discussion_mention |
| 讨论区任务负责人收到留言 | discussion_owner |
| 任务创建邀请 | task_invite |
| 被指定为上游任务负责人 | upstream_task_assigned |
| 卡点一键提醒 | blocker_remind |

判定（domain 规则）：站内通知产生时，以下五项**全部**成立才写一条邮件进 outbox，任一不成立不发：系统总开关开、系统事件开关开、收件人个人总开关开、收件人个人事件开关开、收件人未停用。站内通知行为不变。找回密码邮件不受这些开关控制。

不做：审批待办邮件、每日摘要、其他渠道、按项目的规则。

## 11. 权限矩阵

## 12. 非功能要求

- 部署前提：公有云单机、公网 IP:80、HTTP 明文（ADR 0001 修订）；本模块的防枚举回文、限速与 token 哈希落库都以此为前提设计。
- 系统级审计复用现有写路径装饰器，`audit_logs.project_id` 改可空；后续系统设置写接口自动覆盖，无需手挂。
- 品牌读取接口免登录且只读，不暴露任何账号信息。
- outbox 发送协程随进程启动，进程内单实例，与 ADR 0001 的 time.Ticker 同一形态。

## 15. 已确认的模块决策

1. 系统管理员隐式为所有项目的项目管理员，但不进审批链、不出现在成员列表与选择器；显式成员身份优先。
2. 首个系统管理员与应急恢复只走 CLI；不做迁移自动提权、不做「首个登录者成为管理员」。
3. 账号只停用不删除；停用提示只在用户名与密码都正确时给出。
4. 密码 8～32 位，无其他复杂度规则；所有密码入口共用一条 domain 规则。
5. 「口令」全部改「密码」；代码标识符不动。
6. SMTP 密码 AES 加密落库、密钥来自环境变量；邮件一律经 outbox 异步发送。
7. 邮件只同步既有五类站内通知，三层开关（系统总开关、系统事件开关、个人偏好）与停用状态共同决定；找回密码邮件独立。
8. 品牌四项文字有字符上限，logo 不收 SVG、经后端出图不给对象存储直链。
9. 系统级审计复用项目审计表（项目字段可空）与现有装饰器；本人改密、改资料不审计。
10. 找回密码请求接口挂登录限速、统一回文、token 只落哈希、30 分钟一次性。
