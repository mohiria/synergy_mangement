### PRD 逻辑不完善

| 编号 | 冲突 | 建议 |
|---|---|---|
| Q-04 | AC-31 写「任务概况按基础信息、任务输入、交付物、交付物接收方、当前卡点**五块**排列」，但 #79 落地后实际是**六块**——「过程文件与外部材料」插在交付物与交付物接收方之间。AC-31 文本没跟着改 | 改 AC-31 文本，写明第六块及其位置 |
| Q-05 | §7.7 要求「按 O、KR、任务、文件类型、人员和时间筛选」六维。实现是：O／KR 合成一个下拉、文件类型、时间、**内容状态**（PRD 没写的第四个下拉），任务与人员靠搜索框「搜索交付物、任务或负责人」覆盖 | 裁决：补两个独立下拉，还是把「搜索框覆盖任务与人员」与「内容状态维」写进 §7.7 |
| Q-06 | §7.9／AC-60 叫「提醒冷却」，实现是**每日次数上限**（设置字段 `remindDailyLimit`，按「任务＋发起人＋被提醒人＋日期」计数），提示文案「今天对该成员的提醒次数已用完」。「冷却」通常指时间窗口 | 统一术语（建议「提醒频次上限」），PRD、CONTEXT 词汇表与设置页文案一起改 |
| Q-07 | AC-43 要求点边后「高亮关系两端」。实现是**淡化其余任务节点**来反衬两端，但**成员节点不参与淡化**——选中一条边时其余「关系相关项目成员」节点仍是正常态 | 要么让成员节点同样淡化，要么在 AC-43 写明只淡化任务节点 |
| Q-08 | AC-44 的卡点候选标签直接用 `kindLabel`（「上游未就绪 · 任务名：缺 …」），不含「卡点」二字；而 O／KR／任务／成员／关系候选都有类型前缀（`O ·`／`任务 ·`／`成员 ·`／`关系 ·`）。用户按「卡点」搜不到任何东西 | 给卡点候选补「卡点 · 」前缀 |
| Q-09 | AC-56／基线 §4 的圆角契约是 {4px, 50%}，例外只列了头像、圆点、开关滑块。实测另有两处：antd 通知徽标 `7px`、antd 开关外壳 `100px` | 基线补写这两类胶囊形组件的豁免，否则视觉契约断言口径与实际长期打架 |
| Q-10 | 「显示已完成」默认关闭（AC-45），于是**下属任务全部完成的 KR，其任务关系层是一块只有说明文字的空白画布**（例：KR1.1），没有空态提示 | 补空态：「该 KR 下的任务已全部完成，打开『显示已完成』查看」 |

## 复现方式

本机无 Docker，服务手装在 `~/sdk`：

```bash
~/sdk/pgsql/bin/pg_ctl -D ~/sdk/pgdata -l ~/sdk/logs/postgres.log -o "-p 5432 -k /tmp" start
MINIO_ROOT_USER=synergy MINIO_ROOT_PASSWORD=<取 .env.example 默认值> \
  ~/sdk/bin/minio server ~/sdk/miniodata --address :9000 --console-address 127.0.0.1:9001 &

export PATH=$HOME/sdk/go1.26.7/bin:$PATH
export DATABASE_URL="postgres://synergy@localhost:5432/synergy?sslmode=disable"

cd server && go build ./... && go vet ./... && go test -count=1 ./...
SEED_PASSWORD='<自定口令>' go run ./cmd/seed          # 注意：清空全部业务数据
cd ../web && npm run build && SEED_PASSWORD='<自定口令>' npm run test:e2e
```

标准环境（有 Docker）按 CLAUDE.md 走 `docker compose up -d postgres minio` 即可。Gotenberg 本机起不来，报告导出那条集成测试会自动 skip。

> 本机的 MinIO 用的是 `.env.example` 里的默认凭据，不是仓库根 `.env` 那套；照 `.env` 跑集成测试会得到 `SignatureDoesNotMatch` 403，看着像代码 bug，其实只是 key 不对。
