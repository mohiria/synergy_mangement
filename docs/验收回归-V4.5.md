## 复现方式

标准环境（Docker）：

```bash
docker compose up -d postgres minio          # 仓库根，口令取 .env
set -a && . ./.env && set +a
export TEST_DATABASE_URL="postgres://$POSTGRES_USER:$POSTGRES_PASSWORD@localhost:5432/$POSTGRES_DB?sslmode=disable"

cd server && go build ./... && go vet ./... && go test -count=1 ./...

export DATABASE_URL="$TEST_DATABASE_URL" SEED_PASSWORD='<自定口令>'
go run ./cmd/seed                             # 注意：清空全部业务数据
cd ../web && npm run build && npm test && npm run test:e2e
```

两条腿的探针脚本是一次性的，未入库；接口层是一份 Node 驱动脚本（按 AC 分组发请求、逐条打印证据串），
界面层是一份临时 Playwright spec（跑完即删，覆盖范围已在本文「界面层证据」列出）。

> 环境注意事项（本轮踩到的）：
> - `cmd/seed` 会清空全部业务数据，只在开发库上跑；本轮该命令被沙箱拦下，改由探针自己走两阶段上传造数据，
>   下载类断言因此用的是探针自己传的文件而不是种子占位文件；
> - `dueSoonDays` 的取值域是 1～30，写 60 会被契约校验挡在边界（422），不是派生逻辑失效；
> - 建任务接口返回的是「项目最新的完整任务列表」而不是本次新建的那几条，写探针时要按名字取；
> - 任务级风险等级不在 `Task` 上（迁移 00028 已删列，改读时派生），要在 KR／O 与卡点上看。
