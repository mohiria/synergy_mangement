# 部署说明

公有云单机部署（公网 IP:80、HTTP 明文，ADR 0001「修订：公网部署」）：在服务器上克隆仓库、用 `docker compose` 本地构建并启动，不依赖任何镜像仓库与 CI。

## 前置条件

- Linux 服务器，装好 Docker Engine 与 Docker Compose v2（`docker compose version` 能输出版本）
- 服务器能访问 Docker Hub / Go module proxy / npm 源（构建时要拉基础镜像与依赖）；基础镜像只用 Docker Hub 上的 `golang`、`node`、`caddy`、`minio` 等，不依赖 gcr.io
- 国内服务器如果拉 Docker Hub 慢，给 `/etc/docker/daemon.json` 配 `registry-mirrors` 后 `systemctl restart docker`；Go 与 npm 可设 `GOPROXY=https://goproxy.cn`、`npm config set registry https://registry.npmmirror.com`（在 Dockerfile 里加 ENV/RUN，或用构建参数）
- 云安全组只放行一个端口：`80`（页面、API 与文件上传下载都经 Caddy）；MinIO 的 9000 不对外开放（#194）

## 首次部署

```bash
git clone <仓库地址> /opt/synergy
cd /opt/synergy

cp .env.example .env
vi .env            # 至少填 POSTGRES_PASSWORD、MINIO_ROOT_PASSWORD、MINIO_PUBLIC_ENDPOINT

docker compose up -d --build
```

`.env` 里四个必填项（`POSTGRES_PASSWORD`、`MINIO_ROOT_PASSWORD`、`MINIO_PUBLIC_ENDPOINT`、`APP_SECRET_KEY`）漏填时 compose 会直接报错退出，不会用弱密码把服务跑起来。
`MINIO_PUBLIC_ENDPOINT` 填**用户浏览器访问本站的地址**（公网 IP 或主机名，例如 `203.0.113.10`；`HTTP_PORT` 不是 80 时带上端口）。预签名 URL 以它为 host 生成，由 Caddy 在同一端口按桶名前缀 `/synergy/*` 原样反代到 MinIO——不改路径、透传 Host，签名才能验过；填 `localhost` 会让所有文件上传下载失效。

数据库结构由 `migrate` 服务在 `app` 启动前自动迁移，空库冷启动无需人工干预。

检查：

```bash
docker compose ps
curl -fsS http://localhost/api/v1/healthz
```

## 创建第一个账号

空库没有任何用户，登录页进不去。用镜像里的 `useradd` 建首个账号：

```bash
docker compose run --rm --entrypoint /useradd app \
  -username alice -display 张三 -email alice@example.com -password '你的强密码'
```

之后成员由该账号在系统内管理。

## 重建演示数据（可选）

只在演示／试用环境做。**这条命令会先清空全部业务数据，包括所有用户**——上面用 `useradd` 建的账号也会被删掉，跑之前先确认库里没有要留的东西。

```bash
docker compose run --rm -e SEED_PASSWORD='演示密码' --entrypoint /seed app
```

重建出 15 个账号、4 个项目、共约 660 行业务数据（任务、交付物、审批、协作留痕等），并往 MinIO 写占位文件让下载路径也能走通。全部演示账号的登录密码都是 `SEED_PASSWORD` 的值，用户名见命令输出，例如 `zhaowenqi`。加 `-skip-files` 可跳过占位文件上传。

跑完如果还要一个自己的账号，再执行一次上面的 `useradd`。

## 升级

```bash
cd /opt/synergy
git pull
docker compose up -d --build
docker image prune -f
```

迁移会随之自动执行。回滚就切回上一个 commit 再跑同样的命令（注意迁移不自动回滚，涉及破坏性迁移时先备份）。

## 备份

```bash
# 数据库
docker compose exec -T postgres pg_dump -U synergy synergy > synergy-$(date +%F).sql
# 文件（MinIO 数据卷）
docker run --rm -v synergy_miniodata:/data -v "$PWD:/backup" alpine \
  tar czf /backup/minio-$(date +%F).tar.gz -C /data .
```

卷名以 compose 项目名为前缀，项目名默认取目录名（`/opt/synergy` → `synergy_`），用 `docker volume ls` 确认。

## 磁盘容量

单个交付物文件上限 1 GB（#195）。MinIO 数据卷按「1 GB × 预计文件数」预估并预留余量；单机上数据库、
对象存储与日志共用一块盘，磁盘写满整站受影响，建议对数据盘使用率加告警（例如 80%）。

## 端口与暴露面

| 端口 | 服务 | 绑定 |
| --- | --- | --- |
| 80 | Caddy（SPA + `/api` 反代 + `/synergy/*` 对象存储反代） | 对公网开放，可用 `HTTP_PORT` 改 |
| 9000 | MinIO S3 接口 | 仅 127.0.0.1（本机调试） |
| 9001 | MinIO 控制台 | 仅 127.0.0.1 |
| 5432 | PostgreSQL | 仅 127.0.0.1 |
| 3000 / 8000 | Gotenberg / Apprise | 仅 127.0.0.1 |

公网明文 HTTP（ADR 0001「修订：公网部署」，已知风险与不做项见该节）。日后上 HTTPS 时改 `web/Caddyfile` 的 `:80` 为域名即可，前端代码不用动。

## 排查

文件上传下载失败时先看浏览器 Network 里文件请求的地址：应是 `http://<MINIO_PUBLIC_ENDPOINT>/synergy/...`，
经 80 端口进 Caddy。403 SignatureDoesNotMatch 多半是 `MINIO_PUBLIC_ENDPOINT` 与浏览器实际访问的 host
不一致（预签名按它计算），或 Caddy 改写了路径；连接失败则检查安全组是否只放行了 80。


```bash
docker compose logs -f app        # 应用日志
docker compose logs migrate       # 迁移是否成功退出
docker compose exec postgres psql -U synergy -d synergy
```

### 文件下载不通排查（#117）

上传成功但下载／预览打不开时，按序检查（上传与下载都走 `http://<MINIO_PUBLIC_ENDPOINT>/synergy/...`，
经 Caddy 80 端口反代到 MinIO；上传能成功说明地址与反代大概率没问题，优先查后两条）：

1. **拿到真实下载地址自检**：登录后台任一账号，取一个文件的预签名地址直接 curl：

   ```bash
   # <cookie> 从浏览器复制，或先 curl /auth/login 拿会话
   curl -s -b '<cookie>' http://<服务器>/api/v1/projects/<pid>/files/<fileId>/download-url
   curl -sI '<返回的 url，注意整体加引号>'      # 200 = 链路通
   ```

   - `403`：签名或时钟问题，`docker compose exec app date -u` 与 `date -u` 对比，容器与宿主机时钟偏差应在秒级；
   - `404 NoSuchKey`：对象不存在（演示数据用 `-skip-files` 重建过、或迁移过卷），重传文件即可；
   - 连接超时／拒绝：安全组没放行 80，或 `MINIO_PUBLIC_ENDPOINT` 填了浏览器不可达的地址（不要带 9000，MinIO 已不对外）。
2. **协议一致**：页面走 https 时预签名地址若还是 http 会被浏览器按混合内容拦截，`MINIO_PUBLIC_ENDPOINT` 需与页面同协议（本部署默认全 http，不涉及）。
3. **浏览器侧**：打开开发者工具 Network 看 `download-url` 与后续 `/synergy/...` 请求的实际状态码；若 API 200 而该请求根本没发出，多半是弹窗拦截（旧版本用 `window.open` 打开下载，已在 #117 改为同页跳转，升级后消失）。
