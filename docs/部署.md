# 部署说明

单机内网部署：在服务器上克隆仓库、用 `docker compose` 本地构建并启动，不依赖任何镜像仓库与 CI。

## 前置条件

- Linux 服务器，装好 Docker Engine 与 Docker Compose v2（`docker compose version` 能输出版本）
- 服务器能访问 Docker Hub / Go / npm 源（构建时要拉基础镜像与依赖）
- 对内网开放两个端口：`80`（页面与 API）、`9000`（MinIO，浏览器直连预签名 URL 下载文件）

## 首次部署

```bash
git clone <仓库地址> /opt/synergy
cd /opt/synergy

cp .env.example .env
vi .env            # 至少填 POSTGRES_PASSWORD、MINIO_ROOT_PASSWORD、MINIO_PUBLIC_ENDPOINT

docker compose up -d --build
```

`.env` 里三个必填项漏填时 compose 会直接报错退出，不会用弱口令把服务跑起来。
`MINIO_PUBLIC_ENDPOINT` 必须填**内网用户浏览器能直连**的地址，例如 `192.168.1.20:9000`；填 `localhost` 会让所有文件下载失效（预签名 URL 不经 Caddy 转发，改写路径会破坏签名）。

数据库结构由 `migrate` 服务在 `app` 启动前自动迁移，空库冷启动无需人工干预。

检查：

```bash
docker compose ps
curl -fsS http://localhost/api/v1/healthz
```

## 创建第一个账号

空库没有任何用户，登录页进不去。用镜像里的 `useradd` 建首个账号：

```bash
docker compose run --rm --entrypoint /useradd app \
  -username alice -display 张三 -password '你的强口令'
```

之后成员由该账号在系统内管理。演示数据重置命令（`cmd/seed`）只用于开发环境，未打进部署镜像。

## 升级

```bash
cd /opt/synergy
git pull
docker compose up -d --build
docker image prune -f
```

迁移会随之自动执行。回滚就切回上一个 commit 再跑同样的命令（注意迁移不自动回滚，涉及破坏性迁移时先备份）。

## 备份

```bash
# 数据库
docker compose exec -T postgres pg_dump -U synergy synergy > synergy-$(date +%F).sql
# 文件（MinIO 数据卷）
docker run --rm -v synergy_miniodata:/data -v "$PWD:/backup" alpine \
  tar czf /backup/minio-$(date +%F).tar.gz -C /data .
```

卷名以 compose 项目名为前缀，项目名默认取目录名（`/opt/synergy` → `synergy_`），用 `docker volume ls` 确认。

## 端口与暴露面

| 端口 | 服务 | 绑定 |
| --- | --- | --- |
| 80 | Caddy（SPA + `/api` 反代） | 对内网开放，可用 `HTTP_PORT` 改 |
| 9000 | MinIO S3 接口 | 对内网开放，浏览器直连下载 |
| 9001 | MinIO 控制台 | 仅 127.0.0.1 |
| 5432 | PostgreSQL | 仅 127.0.0.1 |
| 3000 / 8000 | Gotenberg / Apprise | 仅 127.0.0.1 |

内网明文 HTTP（ADR 0001「认证会话」）。日后上 HTTPS 时改 `web/Caddyfile` 的 `:80` 为域名即可，前端代码不用动。

## 排查

```bash
docker compose logs -f app        # 应用日志
docker compose logs migrate       # 迁移是否成功退出
docker compose exec postgres psql -U synergy -d synergy
```
