# 协同推进系统 V4.4 UI Redesign V1

这是从 `collaboration-prototype-v4.3` 独立复制出的 UI 改造版本，旧版本不做覆盖。当前改造已覆盖项目总览、OKR、全部任务、协作关系、我的工作、成果与归档、项目报告、项目设置，以及共用的任务详情、弹窗、筛选、表格和状态反馈；业务数据和既有交互保持一致。

## 推荐演示路径

1. 以“项目总负责人林岚”进入项目总览，展开 KR1，打开 T01 查看“任务概况／讨论／审核”三个 Tab。
2. 在协作关系中通过左侧风险队列定位异常，再切换 KR 聚合、单层聚焦、全局展开和关系列表。
3. 切换“普通参与人苏航”，在全部任务创建任务并提交入池审批。
4. 切换“KR 负责人周宁”，在我的工作 → 待我审批中通过入池申请和关键字段变更。
5. 切换“任务负责人顾言”，从全部任务打开 T02，上报卡点、配置输入来源或一次提交多项候选交付物。
6. 切换“中间审核人陆川”，在待我审批中通过或签审核；再切换周宁完成 KR 最终闭环。
7. 切换苏航，在待我接收中同意输入请求，再填写/上传并提交。
8. 进入成果与归档，查看当前交付物、审核中的候选内容与来源关系边，勾选已生效内容生成阶段成果包。
9. 进入项目报告，切换今天、近 7 天、近 30 天和项目整体，并导出移动端长图或 PDF 演示文件。

## 已实现交互

- V4.4 一级导航、页面标签、搜索与筛选（不含独立“卡点与风险”模块）
- 身份切换、通知入口、权限差异与同一项目事实
- 项目总览 O/KR 展开及任务下钻；任务详情三 Tab、交付物预览／下载、直接协作关系和图谱定位
- 任务平铺讨论流，支持文字和 @ 成员，提交后不可编辑或删除
- 任务入池、关键字段变更和完成审核统一进入审核 Tab，仅当前待行动人可处理
- OKR 表格式录入界面与导入映射预览
- 任务创建、入池审批、退回、关键字段变更审批
- 二维关系图谱：KR 聚合、单层聚焦、全局展开、返回、缩放、画布／节点拖动、小地图、适应屏幕和重新布局
- 关系图谱与关系列表共享 O、KR、人员、任务状态、风险、关系类型和三态时间筛选；默认淡化未命中内容，可主动切换为隐藏
- 搜索先展示 O、KR、任务、关系成员、结构化卡点和交付物边候选，选中后再定位，不随输入扰动画布
- 节点与交付物边只读详情、KR 汇总边解释、当前交付物预览／下载、受影响 O／KR 系统推导和两端任务跳转
- 两种输入来源：已有任务交付物边、指定成员提供
- 手工输入来源审批后通知、同意接收、填写/上传并提交
- 可选多人或签中间审核、线上退回与 KR 最终闭环
- 卡点在任务操作中主动上报，并分散显示于我的工作、总览、图谱和报告
- 每项交付物只保留一份当前内容；候选内容终审后覆盖旧文件，不保留历史文件或版本入口
- 成果与归档页内生成固定阶段成果包并模拟下载
- 项目报告时间切换、移动端长图下载、PDF 演示下载
- localStorage 保存交互结果及“重置演示数据”

## 模拟行为

- 无后端、真实账号、真实消息推送或文件存储；所有状态保存在浏览器 localStorage。
- 上传控件用文件名和可见状态模拟，不向服务器传输文件。
- PDF 是用于验证下载动作的原型文件；移动端长图由浏览器 Canvas 实际生成。
- 图谱布局采用确定性演示排布；关键路径、互锁和反馈关系来自脱敏演示数据，不运行生产级图算法。
- 阶段成果包下载为包含固定目录和来源清单的脱敏文本包，不进行真实压缩。
